# PRD：小红书大家电舆情监控系统第一版

文档状态：已确认，可进入开发前方案设计
确认日期：2026-08-06
产品代号：ReadTrace
优先级：P0

## 1. 产品概述

ReadTrace第一版是一套面向公司内部的小红书舆情分析系统，服务对象包括公司领导层、策划岗和运营岗。

系统按品牌持续获取小红书相关帖子及评论，通过DeepSeek V4分析内容的情感倾向、问题类型、产品品类、用户阶段和风险程度，再将高频关键词归纳为可解释的原因主题。所有分析结论必须能够追溯到原帖或原评论。

第一版聚焦冰箱、空调、洗衣机、电视和热水器等大家电。竞品与自有品牌使用同一套品牌监控能力，不建设独立的竞品模块。

第一版先在本地完成开发和验证，但开发期间直接连接用户提供的云数据库。云服务器部署留到后续任务处理。

## 2. 要解决的问题

现有人工方式通常需要运营人员搜索品牌词、逐篇阅读帖子和评论，再手工整理表格。主要问题包括：

- 内容数量较多，容易遗漏重要负面信息。
- 关键词只能说明用户提到了什么，无法直接说明不满意的原因。
- 帖子、评论、品类和问题类型分散，难以判断变化趋势。
- 领导层看到汇总数字后，难以快速找到支撑结论的用户原话。
- 人工分类标准不一致，后续复盘时无法稳定比较。

## 3. 产品目标

- 按品牌持续获取小红书帖子、评论及互动数据。
- 每小时执行一次数据更新，并允许管理员手动触发更新。
- 将帖子和评论分别完成多维度分析，保留二者之间的上下文关系。
- 展示品牌、品类、问题类型和原因主题随时间的变化。
- 将正向和负向关键词分开统计，并能从关键词或原因主题查看原始证据。
- 允许管理员修正自动分析结果，统计页面使用修正后的有效结果。
- 显示采集状态、更新时间、分类可信度和异常情况，避免把缺失数据解释为零舆情。
- 支持导出筛选后的明细和汇总结果，用于内部汇报和策划研究。

## 4. 目标用户

### 4.1 公司领导层

主要关注整体舆情变化、负面问题排行、风险较高的内容、不同品牌或品类之间的差异，以及支撑结论的典型原文。

### 4.2 策划岗

主要关注用户不满意的原因、正向卖点、问题发生阶段、具体产品或型号，以及能够用于产品策划和传播调整的用户原话。

### 4.3 运营岗

主要关注最近新增的负面内容、高风险帖子、客服投诉、分类是否准确，以及需要提供给其他部门的典型内容。

第一版三类用户共用一个管理员账号，不做角色权限区分。

## 5. 第一版范围

### 5.1 品牌监控

管理员可以创建、编辑、启用和停用品牌监控项。每个监控项包括：

- 品牌名称。
- 品牌简称、旧称和常见错别字。
- 产品系列和型号关键词。
- 排除词。
- 监控起止时间。
- 启用状态。

竞品作为普通品牌监控项录入，与自有品牌使用相同的数据结构、采集逻辑和分析能力。

### 5.2 帖子采集

帖子至少保存以下信息：

- 平台内唯一标识。
- 标题和正文。
- 作者公开信息。
- 发布时间。
- 原帖链接。
- 点赞数、收藏数和评论数。
- 帖子图片及图片文字识别结果。
- 命中的品牌和搜索词。
- 首次采集时间和最后更新时间。
- 原始采集内容或能够复核的原始字段快照。

互动数据会发生变化。系统需要保存当前值，并保留能够计算历史变化的数据记录。

### 5.3 评论采集

评论至少保存以下信息：

- 平台内唯一标识。
- 评论正文。
- 作者公开信息。
- 发布时间。
- 点赞数。
- 所属帖子。
- 父评论或回复对象。
- 评论层级。
- 首次采集时间和最后更新时间。

评论分析需要保留必要上下文，不能只把单条评论孤立交给模型判断。

### 5.4 自动分析

帖子和评论分别分析。自动分析由DeepSeek V4完成，输出结果必须采用可校验的固定字段格式。

| 分析维度 | 第一版取值或规则 |
|---|---|
| 情感倾向 | 正向、中性、负向、无法判断 |
| 内容性质 | 使用分享、购买咨询、客服投诉、品牌评价、营销内容、其他 |
| 问题类型 | 产品质量、功能体验、安装、物流、售后、客服、价格、宣传不符、其他，可多选 |
| 产品品类 | 冰箱、空调、洗衣机、电视、热水器、其他、无法识别 |
| 产品层级 | 整体品牌、产品品类、产品系列、具体型号、无法识别 |
| 用户阶段 | 购买前、配送、安装、使用、维修、售后、无法识别 |
| 风险程度 | 普通、关注、高风险 |
| 分析可信度 | 高、中、低 |

分类词表需要能够配置和扩充。品牌、品类、问题类型和模型名称不能散落在代码中形成无法维护的固定逻辑。

### 5.5 原因主题与关键词

系统分别统计正向关键词和负向关键词。每个关键词至少提供：

- 出现次数。
- 涉及帖子数。
- 涉及评论数。
- 涉及用户数。
- 相关内容总点赞数。
- 与上一统计周期相比的变化幅度。

系统使用DeepSeek V4将相关关键词和内容归纳为原因主题。例如，漏水、积水和排水异常可以归入洗衣机排水异常主题。

每个原因主题必须能够查看：

- 主题说明。
- 情感倾向。
- 涉及品牌、品类、系列或型号。
- 内容数量和变化趋势。
- 代表性原帖和原评论。
- 每条证据的点赞数、发布时间和原始链接。

### 5.6 人工修正

管理员可以修正以下自动分析结果：

- 情感倾向。
- 内容性质。
- 问题类型。
- 产品品类、系列和型号。
- 用户阶段。
- 风险程度。
- 原因主题。

系统必须同时保存模型原始结果、模型版本、分析时间、人工修正结果和修正时间。汇总统计优先使用人工修正结果，没有人工修正时使用模型结果。

### 5.7 数据质量

系统需要提供：

- 帖子和评论去重。
- 同一品牌由多个关键词命中时的合并处理。
- 重复搬运内容识别。
- 疑似营销内容识别。
- 无法识别内容的单独统计。
- 每次采集任务的开始时间、结束时间、状态和错误摘要。
- 最后成功采集时间。
- 数据量异常下降或连续采集失败提示。

采集失败时不得删除或覆盖已经成功取得的数据。界面不得把采集失败显示为零舆情。

### 5.8 搜索、筛选和导出

内容明细至少支持以下组合筛选：

- 时间范围。
- 品牌。
- 产品品类、系列和型号。
- 情感倾向。
- 内容性质。
- 问题类型。
- 风险程度。
- 关键词和原因主题。
- 帖子或评论。

导出范围包括：

- 当前筛选条件下的帖子和评论明细。
- 品牌、品类和问题类型汇总。
- 正向、负向关键词排行。
- 原因主题排行。
- 代表性原文及原始链接。

第一版导出格式使用Excel。

## 6. 页面与功能

### 6.1 登录页

功能：

- 使用单管理员账号登录。
- 登录失败时显示明确原因，不泄露账号是否存在等敏感信息。
- 登录成功后进入舆情总览。
- 未登录访问其他页面时返回登录页。
- 支持安全退出。

### 6.2 舆情总览页

功能：

- 选择时间范围和一个或多个品牌。
- 展示帖子总量、评论总量、负面数量和负面占比。
- 展示正向、中性、负向趋势。
- 展示品牌、品类和问题类型排行。
- 展示增长最快的原因主题。
- 展示高风险帖子和评论。
- 展示数据最后更新时间和采集状态。
- 点击任意图表或排行进入带对应筛选条件的内容明细。

### 6.3 原因与关键词页

功能：

- 在正向和负向之间切换。
- 查看原因主题排行和趋势。
- 查看关键词排行。
- 按品牌、品类、型号、时间和问题类型筛选。
- 点击原因主题查看主题说明和对应证据。
- 点击关键词查看包含该词的原帖和原评论。
- 查看每项证据的点赞数、发布时间和原始链接。

### 6.4 内容明细页

功能：

- 分别查看帖子和评论。
- 使用第5.8节规定的条件组合筛选。
- 查看原文、互动数据、所属帖子和上下文。
- 从评论返回所属帖子。
- 打开小红书原始链接。
- 查看模型分析结果、可信度和人工修正结果。
- 修改允许人工修正的字段。
- 导出当前筛选结果。

### 6.5 品牌监控页

功能：

- 新增、编辑、启用和停用品牌。
- 维护品牌别名、错别字、产品词和排除词。
- 查看每个品牌最后成功采集时间和最近一次任务状态。
- 手动触发单个品牌的数据更新。
- 防止重复创建同一品牌或明显冲突的监控项。

### 6.6 分类配置页

功能：

- 查看和维护产品品类、问题类型和原因主题。
- 启用或停用分类项。
- 为分类项配置显示名称、说明和排序。
- 已经被历史数据引用的分类项只能停用，不能直接删除。

### 6.7 数据状态页

功能：

- 查看每小时采集任务的执行记录。
- 查看任务状态、持续时间、采集数量和错误摘要。
- 查看最后成功时间和连续失败次数。
- 手动重新执行失败任务。
- 查看最近数据量是否出现异常下降。

## 7. 用户故事与验收条件

### US-001：管理员登录

作为管理员，我需要登录系统，以便限制内部舆情数据的访问范围。

验收条件：

- [ ] 正确账号和密码可以登录并进入舆情总览。
- [ ] 错误账号或密码不能登录，错误提示不暴露具体失败字段。
- [ ] 未登录用户无法访问业务页面。
- [ ] 退出后原登录会话立即失效。
- [ ] 在浏览器中验证登录、失败提示、退出和未登录跳转。

### US-002：配置品牌监控

作为管理员，我需要维护品牌及其相关词，以便系统准确查找自有品牌和竞品内容。

验收条件：

- [ ] 可以新增、编辑、启用和停用品牌监控项。
- [ ] 可以维护品牌别名、错别字、产品词和排除词。
- [ ] 停用品牌后不再创建新的定时采集任务，历史数据仍然可查。
- [ ] 重复品牌或明显冲突的配置会被提示。
- [ ] 在浏览器中验证新增、编辑、停用和异常提示。

### US-003：按小时更新数据

作为管理员，我需要系统每小时更新小红书数据，以便看到较新的舆情变化。

验收条件：

- [ ] 启用的品牌每小时会进入一次计划采集流程。
- [ ] 同一品牌同一小时重复触发不会产生重复帖子或评论。
- [ ] 管理员可以手动触发单个品牌更新。
- [ ] 任务记录包含开始时间、结束时间、状态、数据数量和错误摘要。
- [ ] 任务失败不会覆盖已有数据，也不会在总览中显示成零舆情。
- [ ] 连续失败和数据量异常下降能够在界面看到。

### US-004：查看舆情总览

作为领导或业务人员，我需要查看舆情趋势和问题排行，以便判断哪些问题需要重点研究。

验收条件：

- [ ] 可以按时间和品牌筛选总览数据。
- [ ] 可以看到帖子量、评论量、负面数量和负面占比。
- [ ] 可以看到情感趋势、品类排行、问题排行和原因主题排行。
- [ ] 可以看到高风险内容和数据更新时间。
- [ ] 点击图表或排行后进入带对应筛选条件的明细。
- [ ] 总览统计与同条件下的明细数量一致。
- [ ] 在浏览器中验证筛选、图表跳转、空状态和采集异常状态。

### US-005：自动分类帖子和评论

作为策划或运营人员，我需要系统自动识别内容的情感、品类和问题，以便减少逐条阅读的工作量。

验收条件：

- [ ] 新取得的帖子和评论会分别提交给DeepSeek V4分析。
- [ ] 模型输出经过字段格式和取值校验后才写入有效分析结果。
- [ ] 帖子与评论的分析结果不会互相覆盖。
- [ ] 评论分析使用所属帖子和必要回复上下文。
- [ ] 每次分析保存模型名称、模型结果、可信度和分析时间。
- [ ] 模型请求失败后可以重试，失败内容能够被查询。
- [ ] 未通过格式校验的结果不会进入正式统计。

### US-006：查看原因主题和关键词

作为策划人员，我需要查看正向卖点和负面原因，以便找到用户评价集中的内容。

验收条件：

- [ ] 正向和负向关键词分别统计。
- [ ] 关键词显示出现次数、帖子数、评论数、用户数、相关点赞数和变化幅度。
- [ ] 相关内容能够归纳成原因主题。
- [ ] 每个原因主题至少关联一条可查看的原始证据。
- [ ] 点击关键词或主题后可以查看原帖、原评论、互动数、发布时间和链接。
- [ ] 关键词统计不会因为同一内容被重复采集而增加。
- [ ] 在浏览器中验证筛选、排序、跳转和证据回看。

### US-007：查看并修正内容分析

作为运营人员，我需要检查和修正模型判断，以便让后续统计使用更准确的分类。

验收条件：

- [ ] 可以查看帖子、评论、上下文和模型分析结果。
- [ ] 可以修改情感、内容性质、问题类型、品类、型号、阶段、风险和原因主题。
- [ ] 修改后同时保留模型原结果和人工结果。
- [ ] 汇总统计优先使用人工结果。
- [ ] 修正后的内容重新打开时仍然显示修正结果。
- [ ] 在浏览器中验证编辑、保存、失败提示和统计变化。

### US-008：筛选和导出数据

作为领导或业务人员，我需要筛选并导出数据，以便制作内部汇报材料。

验收条件：

- [ ] 支持第5.8节规定的组合筛选条件。
- [ ] 多个筛选条件同时生效，界面显示当前有效条件。
- [ ] 导出内容与当前筛选结果一致。
- [ ] Excel文件包含原始链接、互动数据和有效分析结果。
- [ ] 导出任务失败时显示原因，不生成内容不完整的文件。
- [ ] 在浏览器中验证组合筛选、清除筛选和导出。

### US-009：查看数据状态

作为管理员，我需要知道数据是否按计划更新，以免把采集失败误解为没有舆情。

验收条件：

- [ ] 可以按品牌和状态查看采集任务记录。
- [ ] 可以看到最后成功时间、连续失败次数和错误摘要。
- [ ] 可以重新执行失败任务。
- [ ] 采集异常会在总览和数据状态页同时显示。
- [ ] 在浏览器中验证正常、失败、重试和无历史记录状态。

## 8. 功能性要求

- FR-001：系统必须通过单管理员账号保护所有业务页面。
- FR-002：系统必须允许维护多个品牌，自有品牌与竞品采用相同逻辑。
- FR-003：系统必须支持品牌别名、产品词和排除词。
- FR-004：系统必须每小时为启用品牌执行数据更新，并支持手动更新。
- FR-005：系统必须分别保存帖子、评论及其上下文关系。
- FR-006：系统必须保存帖子和评论的原始链接、采集时间和更新时间。
- FR-007：系统必须记录帖子点赞数、收藏数和评论数，以及评论点赞数。
- FR-008：系统必须识别帖子图片中的文字，视频语音不在第一版范围内。
- FR-009：系统必须使用DeepSeek V4分别分析帖子和评论。
- FR-010：系统必须将情感倾向、内容性质、问题类型、产品品类、产品层级、用户阶段、风险程度和可信度分别保存。
- FR-011：问题类型必须支持多选。
- FR-012：系统必须分别统计正向和负向关键词。
- FR-013：系统必须将相关内容归纳为原因主题。
- FR-014：所有关键词和原因主题必须能够回看对应原帖或原评论。
- FR-015：系统必须允许人工修正自动分析结果并保留两套结果。
- FR-016：所有统计必须优先使用人工修正结果。
- FR-017：系统必须避免重复采集导致统计重复。
- FR-018：系统必须显示采集状态和最后成功时间。
- FR-019：系统必须允许按多个业务维度组合筛选。
- FR-020：系统必须将当前筛选结果导出为Excel文件。
- FR-021：所有分类项必须可以扩充或停用，历史已引用分类不得直接删除。
- FR-022：数据来源设计必须保留以后接入其他内容平台的边界，但第一版只实现小红书。

## 9. 不做事项

第一版不包含：

- 工单、负责人、处理状态和跨部门协作流程。
- 客服回复、自动回复和回复话术生成。
- 短信、邮件、企业微信等消息提醒。
- 用户账号画像和社交关系分析。
- 内容传播路径分析。
- 舆情发展预测。
- 自动生成周报、演示文稿或管理层结论。
- 视频语音识别和视频画面理解。
- 小红书以外的数据平台。
- 独立的竞品模块。
- 多管理员、多角色和权限管理。
- 面向外部客户的多租户、套餐和计费功能。
- 手机应用和小程序。
- 本轮开发中的云服务器部署。

## 10. 技术约束

### 10.1 开发和部署边界

- 第一阶段在本地完成开发、联调和验收。
- 开发期间直接连接用户提供的云数据库，不使用SQLite作为正式开发数据库。
- 云服务器部署、域名、HTTPS、备份和正式运行环境在后续任务处理。
- 本地开发方案需要避免依赖只能在某一台电脑运行的绝对路径或人工操作。

### 10.2 数据库

- 数据库类型、地址、端口、账号和密码由用户在开发开始时提供。
- 数据库连接信息只能通过环境变量或不进入版本控制的本地配置提供。
- 数据库设计需要支持品牌、品类和问题类型扩充。
- 帖子、评论、互动数据历史、模型分析结果和人工修正结果需要分别保存。
- 定时任务需要具备幂等性。同一数据重复取得时更新已有记录，不能新增重复业务数据。
- 所有业务时间统一按Asia/Shanghai展示，数据库时间保存方式需要在技术方案中明确。

### 10.3 小红书数据来源

- 开发第一阶段先验证账号登录、帖子搜索、评论读取和互动数据更新是否能够稳定执行。
- 小红书账号、Cookie及其他登录凭证只能通过本地安全配置提供，不得写入文档、代码、日志或提交记录。
- 采集方案需要控制访问频率，并单独评估平台规则、账号风险、个人信息保护和内部使用边界。
- 公开作者信息只保存完成内部分析所需的最少字段。
- 数据来源暂时无法取得的字段需要明确显示为缺失，不能伪造或推断原始互动数据。

### 10.4 DeepSeek V4

- 自动分类和原因归纳使用用户提供账号对应的DeepSeek V4服务。
- API地址、密钥和具体模型标识通过环境变量配置。
- 模型调用必须要求固定字段输出，并在写入数据库前完成格式和取值校验。
- 需要记录模型标识、提示词版本、分析时间、原始结果和有效结果。
- 模型调用需要设置超时、有限次数重试和失败记录。
- 密钥不得写入代码、文档、日志、测试数据或提交记录。
- 模型接口应集中封装，后续更换模型时不需要改动采集和页面逻辑。

### 10.5 安全

- 管理员密码不能明文保存。
- 登录会话需要设置合理有效期并支持服务端失效。
- 所有业务接口都要验证登录状态。
- 导出文件只能由已登录管理员生成和下载。
- 日志不得记录密码、数据库连接串、Cookie、Token、模型密钥和完整登录请求。
- 面向页面展示的原始内容需要避免脚本注入。

### 10.6 可观察性与错误处理

- 采集任务、模型任务和导出任务都需要记录状态和错误摘要。
- 外部服务失败时保留已经成功的数据，并允许安全重试。
- 页面需要区分无数据、尚未采集、采集失败和筛选后没有结果。
- 关键错误日志需要包含任务标识和发生时间，但不包含敏感凭证。

### 10.7 扩展性

- 品牌、分类词表和模型配置不能写死在页面或散落在业务逻辑中。
- 数据来源应有独立接入边界，第一版只实现小红书来源。
- 原始数据、标准化数据和分析结果应保持区分，后续重新分析时不需要重新采集全部内容。
- 页面统计不得直接依赖某个具体模型的非标准文本回答。

## 11. 整体验收标准

### 11.1 数据获取

- [ ] 使用用户提供的小红书账号，可以通过至少一个测试品牌取得相关帖子。
- [ ] 可以取得帖子正文、发布时间、原始链接及能够访问到的互动数据。
- [ ] 可以取得帖子评论、评论层级、所属帖子及能够访问到的评论点赞数。
- [ ] 同一帖子和评论重复采集不会形成重复数据。
- [ ] 已有帖子的互动数据可以在后续任务中更新。
- [ ] 每小时调度能够连续运行24小时，并保留每次任务记录。
- [ ] 单次失败不会删除历史数据，管理员可以重新执行失败任务。

### 11.2 自动分析

- [ ] DeepSeek V4能够按照约定字段返回帖子和评论分析结果。
- [ ] 非法字段、非法分类值和缺失必要字段不会进入正式统计。
- [ ] 评论分析包含帖子或回复上下文。
- [ ] 负向内容可以归入一个或多个问题类型。
- [ ] 每个原因主题都能查看至少一条原始证据。
- [ ] 人工修正后，明细和汇总都使用修正结果。

### 11.3 页面和交互

- [ ] 七个P0页面都能在主流桌面浏览器正常使用。
- [ ] 总览、原因关键词和明细页共享一致的筛选口径。
- [ ] 图表、排行、关键词和原因主题都能进入对应证据明细。
- [ ] 原帖链接能够从明细页直接打开。
- [ ] 无数据、采集失败、加载中和筛选无结果分别显示对应状态。
- [ ] 所有页面功能完成浏览器实际操作验证。

### 11.4 导出

- [ ] Excel导出结果与当前筛选条件一致。
- [ ] 导出文件包含原文、原始链接、互动数据和有效分类结果。
- [ ] 中文内容打开后没有乱码。
- [ ] 导出失败不会向用户提供不完整文件。

### 11.5 安全和配置

- [ ] 仓库中不存在真实账号、Cookie、数据库密码和模型密钥。
- [ ] 密码以安全散列形式保存。
- [ ] 未登录状态无法访问业务接口或下载导出文件。
- [ ] 日志中不存在敏感凭证。
- [ ] 更换数据库连接或模型密钥时不需要修改代码。

### 11.6 基础性能

- [ ] 在包含1万篇帖子和10万条评论的验收数据集上，常用明细查询和总览查询在正常网络条件下95％请求不超过3秒。
- [ ] 大批量导出使用后台任务或流式生成，不阻塞其他页面查询。
- [ ] 每小时任务尚未完成时不会重复启动同一品牌的并发采集任务。

## 12. 开发顺序要求

开发任务应按以下顺序推进，每个阶段验证通过后再进入下一阶段：

1. 验证小红书账号登录、帖子获取、评论获取和互动数据更新。
2. 确认云数据库类型和连接方式，设计数据模型及迁移方案。
3. 验证DeepSeek V4固定字段输出、失败重试和成本情况。
4. 实现采集、去重、定时更新和任务记录。
5. 实现自动分析、原因主题和人工修正。
6. 实现登录和七个P0页面。
7. 实现Excel导出、异常状态和整体验收。

数据获取验证失败时，应先记录实际能够取得和无法取得的字段，再由用户决定缩小范围或更换数据方案，不得用模拟数据掩盖采集问题。

## 13. 待开发任务确认的信息

以下信息不影响本PRD定稿，但会影响开发启动：

- 云数据库类型、连接地址、数据库名称和权限范围。
- 小红书测试账号的安全提供方式。
- DeepSeek V4的API地址、具体模型标识和密钥提供方式。
- 首批监控品牌及品牌别名。
- 第一批产品系列和型号词表。
- 产品品类、问题类型和原因主题的初始配置是否需要业务人员复核。

## 14. 成功判断

第一版成功的判断标准是，业务人员能够从某个品牌近期的负面变化出发，找到增长较快的问题和产品品类，查看支撑结论的原帖及原评论，并把筛选结果导出用于内部分析。整个过程不需要业务人员直接查询数据库或人工整理多份来源文件。
