# ReadTrace浏览器自动采集扩展需求拆解与验收标准

文档状态：拆解中
确认日期：2026-08-06
功能范围：Chrome与Edge Manifest V3自动采集扩展、多节点调度、MySQL入库和DeepSeek异步分析

## B1 实体生命周期与牵连关系

### 1. 采集节点

代表一台安装扩展的办公电脑，不与固定员工绑定。

生命周期：

```text
待绑定 → 在线未登录 → 在线可采集 → 正在采集 → 暂停
                                      ↘ 等待重新登录 → 用户确认恢复 → 在线可采集
任意在线状态 → 离线
任意非撤销状态 → 已撤销
```

牵连关系：

- 节点上线且小红书登录有效后才能领取采集任务。
- 小红书登录失效、出现验证码或访问限制时，节点进入“等待重新登录”，当前任务暂停。
- 用户重新登录并点击“恢复采集”后，节点才能重新进入“在线可采集”。
- 节点离线时，已经上传的数据继续保留，未完成任务等待租约过期后重新分配。
- 节点被撤销后，绑定凭证立即失效，历史任务和采集数据继续保留。
- 一个节点同一时间只能运行一个品牌任务。

### 2. 节点绑定凭证

生命周期：

```text
一次性绑定码 → 已兑换 → 有效凭证 → 自动轮换 → 已过期或已撤销
```

牵连关系：

- 绑定码只能使用一次。
- 凭证只允许领取任务、上传采集结果和上报节点状态。
- 凭证不能访问管理员功能、MySQL或DeepSeek。
- 撤销节点时，节点凭证一起失效。
- 数据库只保存凭证摘要，不保存明文。
- 小红书Cookie和Token不属于节点凭证，不保存也不上传。

### 3. 采集计划

生命周期：

```text
草稿 → 已启用 → 正在调度 → 已暂停 → 重新启用 → 已归档
```

牵连关系：

- 计划关联品牌、搜索词、排除词、每小时频率、搜索结果上限、详情上限、评论上限和评论回访规则。
- 品牌停用后不再创建新任务，已经运行的任务允许安全结束，历史数据继续保留。
- 修改上限只影响后续任务，不修改历史任务。
- 节点每次从服务端领取计划，不在本地永久保存完整计划。

### 4. 采集任务

复用现有`collection_tasks`并补充节点执行状态。

生命周期：

```text
等待领取 → 已分配 → 正在搜索 → 正在采集详情 → 正在采集评论 → 正在上传 → 成功
                              ↘ 部分成功
                              ↘ 等待重新登录或人工验证
                              ↘ 节点离线
                              ↘ 已取消
                              ↘ 失败
```

牵连关系：

- 每个任务只对应一个数据来源和一个品牌。
- 同一品牌同一时间只能有一个运行任务，同一小红书账号不能在多个节点同时采集。
- 任务部分成功时，已经入库的数据不回滚。
- 登录失效或验证码出现时保存进度，不把任务显示为零数据。
- 节点离线后等待租约过期再重新分配。
- 错过的小时任务记录为节点不可用，不集中补跑。

### 5. 任务租约

复用现有`collection_locks`并增加节点所有权。

生命周期：

```text
未持有 → 节点取得租约 → 定期续租 → 正常释放
                         ↘ 节点离线或暂停后过期 → 其他节点接管
```

牵连关系：

- 租约同时约束品牌和节点。
- 旧节点恢复时，如果租约已经被接管，不能继续作为原任务上传。
- 上传接口同时校验节点、任务和租约所有权。
- 节点不能指定或伪造其他品牌任务。

### 6. 采集检查点

生命周期：

```text
任务开始时创建 → 搜索进度更新 → 帖子进度更新 → 评论进度更新 → 任务完成后封存
```

至少记录当前品牌、当前搜索词、已处理搜索结果、当前帖子ID、已完成帖子ID、评论游标、已采集评论数量、是否还有更多评论和最近保存时间。

牵连关系：

- 扩展后台被Chrome暂停后从检查点恢复。
- 节点离线前尽量把检查点上传服务端，其他节点接管时从服务端检查点继续。
- 已经确认入库的上传批次不能因为检查点回退而重复入库。

### 7. 帖子评论回访计划

生命周期：

```text
首次发现 → 活跃回访 → 降低频率 → 暂停回访 → 人工重新关注 → 恢复回访
```

默认规则：

- 高风险帖子和评论增长明显的帖子每小时回访。
- 普通新帖子每6小时回访。
- 发布超过3天且仍有增长的帖子每天回访。
- 发布超过7天且连续没有新增评论的帖子暂停回访。
- 人工持续关注的帖子保持每小时回访。

牵连关系：

- DeepSeek识别出高风险后提高后续评论回访优先级。
- 回访只取得新增评论，通过评论ID去重。
- 高风险分析尚未完成时按照普通新帖规则执行。
- 帖子不可访问时保留历史证据并记录异常。

### 8. 上传批次

生命周期：

```text
本地待上传 → 正在上传 → 服务端已接收 → 已校验 → 已入库
            ↘ 网络失败后等待重试
            ↘ 格式错误或租约失效后拒绝
```

牵连关系：

- 每个批次具有唯一`batchId`，重复上传返回原结果，不重复生成数据。
- 一个批次只属于一个节点、一个任务和一个品牌。
- 帖子与所属评论尽量放在同一批次。
- 扩展只保留尚未确认入库的批次，服务端确认后才能清理。

### 9. 帖子、评论和互动快照

复用现有`posts`、`comments`、互动快照、原始字段快照和品牌命中关系。

生命周期：

```text
首次发现 → 重复采集时更新 → 追加互动快照 → 追加新评论 → 保留历史证据
```

牵连关系：

- 同一平台帖子ID只对应一篇帖子，同一评论ID不能跨帖子移动。
- 缺失互动数不能覆盖已有有效数值。
- 原始快照入库前必须脱敏。
- 采集任务失败不能删除帖子、评论和历史证据。

### 10. DeepSeek分析记录

复用现有`analysis_records`及其关联表。

生命周期：

```text
待分析内容 → 分析任务领取 → 正在分析 → 分析成功
                           ↘ 格式校验失败或请求失败 → 等待重试或最终失败
```

牵连关系：

- 数据成功入库后才进入分析，帖子和评论分别分析。
- 同一内容、模型和提示词版本保持幂等。
- DeepSeek失败不能要求扩展重新采集。
- 新评论独立分析，不覆盖帖子分析。
- 分析结果不修改原始内容，人工修正优先于模型结果。

### 11. 节点事件记录

生命周期：

```text
事件发生 → 写入只追加记录 → 只读保留
```

记录节点上线和离线、登录状态变化、任务领取和完成、验证码或访问限制、页面结构异常、扩展版本变化和凭证撤销。禁止记录Cookie、Token明文、密码、完整请求头和无关浏览历史。

## B2 五个必问

### Q1 空状态

- 扩展尚未绑定：显示一次性绑定码输入框，绑定前不能领取任务、采集或上传；服务器地址由安装包预设，不接受任意上传地址。
- 已绑定但小红书未登录：显示“等待登录小红书”和登录入口，不创建采集标签页、不领取任务。
- 已登录但没有启用品牌：节点保持在线并定时查询任务，不使用默认品牌或搜索词。
- 任务已经被其他节点领取：显示“节点在线，等待任务”和下一次检查时间。
- 数据库尚无采集结果：总览显示首次采集尚未完成、在线节点和任务状态，不把缺失数据显示为零舆情。

### Q2 操作失败

- 小红书登录失效、验证码或访问限制：立即停止页面操作，保存检查点，节点和任务进入等待重新登录；不自动重试，用户重新登录并点击恢复后重新确认租约。
- 扩展到ReadTrace网络中断：未确认批次保存在有容量上限的本地队列，网络恢复后按原`batchId`重传；队列满时暂停采集，不丢弃旧批次。
- 凭证失效或节点被撤销：API返回401或403，扩展停止采集并清除失效凭证，显示重新绑定入口。
- MySQL不可用：上传不标记成功，扩展保留批次并暂停新采集；恢复后重传，不把数据库故障记为小红书采集失败。
- 页面结构变化：单篇失败记录缺失字段，连续3篇详情解析失败后停止任务；成功内容继续上传，空值不覆盖已有有效字段。
- DeepSeek失败：已入库内容继续保留，分析任务独立重试，扩展采集任务不回滚也不重复采集。

### Q3 数据被引用

- 品牌和搜索词修改只影响后续任务；运行任务使用领取时的配置快照，历史命中关系保留原搜索词快照。
- 品牌只能停用或归档；停用后不再创建新任务，当前任务完成当前帖子后停止，历史证据继续保留。
- 节点被撤销后不再续租，已上传数据保留；重新绑定后只允许上传经服务端校验且仍属于原任务的残留批次。
- 来源帖子或评论被删除时，保留历史证据、分析结果和最后访问异常，页面显示来源不可访问。
- 原始内容更新后创建新分析版本，旧分析保留，人工修正不被重新分析覆盖。

### Q4 并发

- 同一品牌只有取得现有品牌租约的节点可以执行，其他节点继续等待任务。
- 同一节点有活跃任务时不分配第二个任务；浏览器重启先恢复原任务。
- `batchId`唯一，重复上传返回首次处理结果，不重复写入数据或分析任务。
- 旧节点恢复时必须重新校验租约；租约已经被接管时返回409，旧节点停止并保留未确认批次供管理员处理。
- 扩展只读取小红书公开账号ID并通过HTTPS提交；服务端使用服务器密钥计算HMAC摘要后丢弃原值，数据库和日志只保留摘要。同一账号摘要同一时间只允许一个采集节点运行。

### Q5 后悔和撤销

- 用户暂停自动采集时停止继续导航，已取得数据正常上传，检查点保留，暂停后不领取新任务。
- 管理员可以取消等待或运行任务；扩展完成当前安全上传后停止，已入库数据不删除，任务使用独立`cancelled`状态。
- 撤销节点需要二次确认，凭证立即失效，任务停止续租，历史数据和事件保留；再次使用必须重新绑定。
- 扩展不提供删除采集数据的能力；删除数据进入独立后台数据治理流程并检查证据、分析、人工修正和个人信息引用。
- 采集规则保留版本；修改只影响后续任务，正在运行的任务继续使用旧版本快照，允许管理员恢复上一版本。

## B3 输入输出链

### 输入

#### 1. 管理员品牌与搜索规则

- 输入：品牌、别名、系列和型号词、排除词、启用状态、采集频率、搜索和详情上限、评论上限、回访策略及规则版本。
- 风险处理：空搜索词计划不能启用；重复词保存时去重；运行任务使用配置快照；品牌较多时拆成独立任务。服务端配置是唯一可信来源，扩展不能自行增加品牌或修改上限。

#### 2. 节点绑定信息

- 输入：一次性绑定码、节点ID、扩展版本、浏览器类型和主版本、操作系统及节点显示名称。
- 风险处理：绑定码过期或已使用时拒绝；低于最低版本的扩展不能领取任务；重复节点ID不能覆盖有效节点；所有过期和租约判断使用服务器UTC时间。

#### 3. 小红书登录状态

- 输入：登录是否有效、公开账号ID、重新登录页面、验证码和访问限制信号。
- 风险处理：无法识别时按照未登录处理；公开账号ID缺失时不领取任务；账号切换时暂停旧任务；原始账号ID只用于服务端计算HMAC摘要后立即丢弃。

#### 4. Chrome生命周期事件

- 输入：每小时定时事件、浏览器启动、扩展更新、网络恢复、用户恢复采集和标签页加载完成。
- 风险处理：电脑休眠后只执行最新周期；浏览器关闭时节点离线；状态写入`chrome.storage`；扩展更新前保存检查点；重复事件不重复创建执行流程。

#### 5. 服务端采集任务

- 输入：任务ID、租约令牌和期限、品牌配置快照、搜索词、排除词、数量上限、评论回访目标、检查点、规则版本和数据格式版本。
- 风险处理：字段缺失、版本不支持、租约过期、品牌不一致或检查点损坏时拒绝执行并报告稳定错误代码。

#### 6. 小红书公开页面

- 输入：搜索结果、帖子详情、已经正常加载的评论和回复、结构化页面状态、公开互动数和页面状态提示。
- 风险处理：缺失字段保留`null`；连续3篇结构失败后停止；临时访问参数不入库；Cookie、Token和敏感请求头必须脱敏；评论通过平台ID去重；来源不可访问时不覆盖历史内容。

#### 7. 上传批次

- 一个批次最多包含1篇帖子、50条评论、互动快照、品牌命中关系、脱敏允许字段快照和评论检查点。
- 未压缩JSON不超过1MB；超过限制时拆分评论批次；图片只保存来源地址，不下载或上传图片文件。
- 413表示需要拆分；422表示字段校验失败；403表示节点或任务不匹配；409表示租约、版本冲突；重复`batchId`返回首次处理结果。

### 输出

#### 1. 节点状态和事件

- 输出到节点管理、数据状态和后续告警。
- 空闲节点每5分钟心跳，运行节点通过续租同时上报；普通心跳不逐条写事件；错误只保存代码、阶段和缺失字段。

#### 2. 任务、租约和检查点

- 输出到调度器、其他节点、状态页面和重试流程。
- 过期续租不能重新激活；检查点使用递增版本；节点离线后等待租约过期；人工取消后完成当前安全上传再停止。

#### 3. MySQL帖子、评论和证据

- 输出到总览、内容明细、品牌统计、互动趋势、分析任务和人工修正。
- 使用平台ID和`batchId`多层幂等；单篇事务失败不影响其他帖子；扩展和服务端执行两层脱敏；查询必须分页；来源失效时保留历史证据。

#### 4. DeepSeek分析队列

- 入库成功后由独立服务端工作进程或定时任务自动分析尚无有效结果的帖子和评论。
- 模型不可用不影响采集；格式错误结果不进入统计；内容版本、模型和提示词版本组成幂等键；显示积压数量；高风险结果只调整后续回访计划，不立即命令扩展访问。

#### 5. ReadTrace页面

- 展示节点状态、任务进度、小时成功率、新增帖子评论、分析积压、分析失败和高风险证据。
- 采集失败不得显示为零舆情；未分析内容不能伪造情感结果；不同节点数据按内容ID去重；节点撤销后历史数据继续可查。

## B4 子功能优先级

### 工作包A：节点、任务和上传底座

V1必须完成节点表、一次性绑定、凭证摘要和撤销、账号HMAC摘要、规则版本、任务状态扩展、节点与品牌租约、检查点、上传批次幂等，以及绑定、心跳、领取、续租、暂停、恢复、完成、检查点和上传API。上传复用现有持久化服务，成功入库后产生待分析内容。

### 工作包B：浏览器自动采集扩展

V1必须完成Manifest V3结构、绑定和状态界面、登录识别、账号摘要上报、定时唤醒、任务领取、独立采集标签页、搜索结果提取、排除词过滤、详情与评论采集、本地检查点和上传队列、重试恢复、登录和验证码暂停，以及任务结束后的页面清理。扩展不能操作用户自己的标签页。

### 工作包C：自动DeepSeek分析

V1必须完成独立分析工作进程，分别领取帖子和评论，复用现有DeepSeek客户端、格式校验和租约，保留失败和积压统计，高风险结果更新评论回访优先级。分析进程异常不影响API和采集。

### 工作包D：ReadTrace管理页面

V1必须完成节点列表、节点状态、绑定码生成、撤销、当前任务、登录异常、进度、取消、结构异常、分析积压、品牌规则和评论回访配置。页面不能暴露凭证、租约令牌、账号原始ID或内部错误堆栈。

### 应该在V1完成

- 浏览器通知和扩展图标状态。
- 最低扩展版本和升级提示。
- 本地队列容量、下次执行时间和本轮数量。
- 节点显示名称、管理员暂停和恢复。
- 高风险、普通新帖、活跃旧帖和无新增帖的分级回访。
- 来源不可访问状态、节点事件保留周期和安装升级说明。

### 可以延后到V2

- 企业微信或飞书通知、Chrome商店自动发布、多租户、其他浏览器、图片下载和OCR。
- 同机账号轮换、节点动态调量、未确认批次人工迁移、复杂负载均衡和账号风险评分。

### 开发顺序

```text
数据库与共享契约 → 节点和任务API → 上传与持久化
→ 可安装扩展和节点绑定 → 自动任务编排 → 页面和评论提取
→ 中断恢复与安全暂停 → 自动DeepSeek分析 → 管理页面 → 全链路验收
```
