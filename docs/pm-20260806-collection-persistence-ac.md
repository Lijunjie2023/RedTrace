# 采集数据持久化与迁移验收标准

状态：拆解中
确认日期：2026-08-06
参考需求：`tasks/prd-xiaohongshu-public-opinion-v1.md`

## 范围

首个迁移版本只覆盖采集与配置数据，包括品牌监控项、品牌搜索词、采集任务、帖子、评论、互动快照、脱敏原始字段快照、品牌命中关系、采集游标与任务锁。

DeepSeek分析结果、人工修正、原因主题、页面和导出不在本工作包中。在模型固定字段输出完成验证后，再为分析数据建立后续迁移。

## B1 实体生命周期与牵连关系

### 品牌监控项

生命周期：草稿 → 启用 → 停用 → 重新启用；草稿或停用状态可以归档。

牵连关系：

- 启用后允许创建采集任务，停用或归档后不得创建新的定时采集任务。
- 停用、归档和修改品牌信息不得删除历史帖子、评论、互动快照、命中关系或采集任务。
- 品牌搜索词从属于品牌监控项，搜索词可以独立启用和停用。

### 品牌搜索词

生命周期：创建 → 启用 → 停用 → 重新启用；未被历史任务引用时可以归档。

牵连关系：

- 搜索词区分别名、型号词和排除词。
- 同一帖子可以命中同一品牌的多个搜索词，通过命中关系保留证据，汇总时按帖子唯一标识去重。
- 搜索词修改后只影响后续采集，历史命中关系保留当时使用的搜索词引用或快照。

### 采集任务

生命周期：等待 → 运行中 → 成功、部分成功或失败；失败和部分成功任务可以重试并产生新的执行记录。

牵连关系：

- 任务开始时取得品牌级互斥锁，同一品牌已有运行中任务时不得重复启动。
- 单篇读取失败时保留已经成功写入的数据，任务标记为部分成功并记录脱敏错误摘要。
- 任务失败不得删除、清空或覆盖历史成功数据。
- 重试保留原任务记录，并通过重试来源关系关联新的执行记录。

### 帖子

生命周期：首次发现 → 持续更新 → 暂时不可访问；后续再次访问成功时恢复更新。

牵连关系：

- 按数据来源和平台帖子ID唯一，重复采集更新同一业务记录。
- 暂时无法访问时保留最后一次成功取得的内容，不将字段清空为`null`。
- 帖子被评论、互动快照、原始字段快照和品牌命中关系引用，不允许物理删除。

### 评论

生命周期：首次发现 → 持续更新 → 暂时不可访问；后续再次访问成功时恢复更新。

牵连关系：

- 按数据来源和平台评论ID唯一，重复采集更新同一业务记录。
- 评论必须引用所属帖子；二级回复可以引用父评论和回复对象。
- 父评论暂未取得时允许先保留平台父评论ID，后续采集取得父评论后补齐内部关联。
- 暂时无法访问时保留最后一次成功取得的内容，不物理删除。

### 互动快照

生命周期：随每次成功取得互动数据而追加，创建后不可修改和删除。

牵连关系：

- 帖子快照记录点赞、收藏、评论和分享数量；评论快照记录点赞数量。
- 原始字段缺失时保存为`null`，不得把缺失写成零。
- 同一任务对同一内容重复处理时不得产生重复快照。

### 原始字段快照

生命周期：采集时创建，完成脱敏后保存，创建后不可修改。

牵连关系：

- 快照引用对应帖子或评论及采集任务，用于复核标准化字段。
- 保存前移除Cookie、Token、手机号、密码和其他登录凭据。
- 脱敏或序列化失败时不得保存未脱敏原文，任务记录对应失败。

### 品牌命中关系

生命周期：采集命中时创建，重复命中时保持唯一；历史关系不因搜索词停用而删除。

牵连关系：

- 关联品牌、搜索词、帖子和首次命中的采集任务。
- 同一品牌、搜索词和帖子组合只允许一条关系。

### 采集游标与任务锁

生命周期：任务开始时创建或取得锁 → 任务结束或租约到期后释放；游标仅在对应阶段成功后推进。

牵连关系：

- 锁按数据来源和品牌隔离，避免小时任务与手动任务同时采集同一品牌。
- 进程异常退出后允许根据租约过期时间安全接管，不能形成永久死锁。
- 失败任务不得把游标推进到未成功处理的位置。

## B2 五个必问

### Q1 空状态

- 空数据库执行迁移后具备完整表结构和基础数据来源配置。
- 没有品牌监控项时不创建采集任务。
- 品牌已经启用但尚未执行采集时，保存尚未执行状态，不得把尚未采集解释为零舆情。

### Q2 操作失败

- MySQL连接失败时，程序启动检查失败，不执行采集，也不产生虚假的成功任务记录。
- 单篇帖子写入失败时，回滚该篇帖子、评论、互动快照、原始字段快照和命中关系的本次写入；其他已经成功写入的帖子继续保留，任务标记为部分成功。
- 整个任务在取得数据前失败时，任务标记为失败，不修改帖子、评论和采集游标。
- 原始数据脱敏失败时，不保存该份原始字段快照，也不允许未脱敏内容进入日志。
- 数据库权限不足或迁移版本不一致时立即停止，不通过删表、跳过迁移或关闭约束绕过错误。

### Q3 数据被引用

- 品牌监控项、搜索词、帖子、评论和采集任务采用归档或状态变更，不开放物理删除。
- 外键阻止删除仍被其他记录引用的数据。
- 搜索词修改、停用或归档后，历史命中记录继续保留。
- 帖子和评论内容更新时，互动快照和原始字段快照继续保留历史版本。

### Q4 并发

- 数据库唯一约束保证帖子、评论和命中关系不重复。
- 写入采用原子更新，同一内容被重复采集时更新现有记录。
- 同一数据来源、同一品牌只允许一个运行中的采集任务。
- 任务锁使用租约到期时间，进程异常退出后允许其他任务安全接管。
- 不同品牌允许并行采集，应用连接池需要适配1核、2GB内存的MySQL规格。

### Q5 后悔与撤销

- 品牌监控项和搜索词可以停用、重新启用或归档。
- 采集数据不提供批量撤销，错误数据通过后续重新采集修正并保留历史证据。
- 数据库迁移采用只向前升级策略，不自动执行可能丢失数据的回滚。
- 涉及删列、删表或改变唯一约束的迁移必须单独确认并先完成备份。
- 测试环境可以清空测试数据，云数据库不得由测试命令执行清库操作。

## B3 输入输出链

### 输入

- 项目根目录`.env.local`中的MySQL连接配置。配置缺失、格式错误或连接失败时停止启动，不执行采集。
- 品牌监控项与品牌搜索词配置。没有启用品牌或有效搜索词时不创建采集任务。
- 小红书采集探针输出的标准化帖子、评论、互动数据与脱敏原始字段。字段缺失时保存为`null`，不得推断为零或空文本。
- 手动触发或每小时调度产生的任务请求。重复触发时由数据来源与品牌维度的任务锁阻止并发执行。
- 版本化数据库迁移文件。数据库迁移版本高于当前程序可识别版本时停止启动，不尝试降级。

### 输出

- 标准化帖子与评论，供后续DeepSeek分析、明细查询和原始证据回看使用。
- 互动历史快照，供趋势和变化幅度计算使用。
- 脱敏原始字段快照，供字段复核和后续重新标准化使用。
- 品牌与搜索词命中关系，供解释内容为什么进入监控范围使用。
- 采集任务状态、错误摘要、最后成功时间、连续失败信息、任务锁和采集游标，供调度和数据状态页面使用。

### 上下游边界

- 后续分析、页面和导出读取标准化数据，不直接依赖探针原始JSON结构。
- DeepSeek分析或页面尚未实现时，已经取得的采集数据仍然正常入库。
- 下游处理失败不得回滚或删除已经成功保存的采集数据。
- 互动快照和原始字段快照采用索引和分批写入控制增长，本阶段不自动清理历史证据。
- 上游字段结构变化导致无法标准化时，保留能够安全保存的脱敏证据并记录结构错误，不写入伪造字段。

## B5 验收标准

### AC-1：配置加载和敏感信息保护

- 前置：`.env.local`分别处于字段完整、字段缺失、端口非法和密码包含特殊字符四种情况。
- 操作：执行数据库健康检查或迁移命令。
- 期望：完整配置能够建立连接；字段缺失或格式非法时在连接前失败并指出字段名；输出和异常不得包含主机地址、账号、密码、完整连接串或SSL证书内容；真实配置文件保持在Git忽略范围内。
- 关联子功能：必须实现1。

### AC-2：新数据库迁移与版本检查

- 前置：目标数据库中不存在ReadTrace业务表，账号具备DDL和DML权限。
- 操作：执行迁移命令两次。
- 期望：第一次按照版本顺序创建全部采集阶段表、约束和索引，并在迁移记录中保存版本、名称和执行时间；第二次不重复建表、不删除数据并返回无待执行迁移；数据库存在高于程序可识别的迁移版本时命令失败且不修改结构。
- 关联子功能：必须实现2、3。

### AC-3：数据来源与品牌配置

- 前置：迁移已经完成。
- 操作：读取小红书数据来源，创建品牌监控项及别名、型号词和排除词，再执行停用、重新启用和归档。
- 期望：小红书数据来源按照稳定代码唯一；品牌名称在同一数据来源内唯一；搜索词类型采用独立字段；停用或归档后历史命中关系仍然存在；归档品牌不得创建新的采集任务。
- 关联子功能：必须实现3，应该实现2。

### AC-4：帖子幂等写入

- 前置：同一数据来源和平台帖子ID存在两份采集结果，第二份正文和互动数据发生变化。
- 操作：在两个采集任务中依次写入两份结果。
- 期望：帖子表只有一条业务记录；正文和最后采集时间更新；首次采集时间保持不变；来源链接和平台帖子ID可回溯；第二次缺失的字段不得清空第一次已经成功取得的值；不同数据来源允许使用相同平台帖子ID。
- 关联子功能：必须实现4、10。

### AC-5：评论层级和幂等写入

- 前置：采集结果包含一级评论、二级回复、暂未取得的父评论以及重复评论记录。
- 操作：写入评论并再次执行相同任务数据。
- 期望：同一数据来源和平台评论ID只产生一条评论；评论引用所属帖子；已取得父评论时保存内部父评论关联；父评论暂缺时保留平台父评论ID，后续取得父评论后补齐内部关联；重复执行不增加记录数量。
- 关联子功能：必须实现4、10。

### AC-6：互动快照与缺失值

- 前置：同一帖子和评论分别在两个采集任务中取得不同互动数量，其中一个原始互动字段缺失。
- 操作：写入两次采集结果，并在同一任务中重复处理一次。
- 期望：每个内容在每个任务中最多产生一条对应类型的互动快照；不同任务保留两条历史快照；缺失字段保存为`null`而不是零；帖子快照包含点赞、收藏、评论和分享数量，评论快照包含点赞数量。
- 关联子功能：必须实现5。

### AC-7：品牌命中关系去重

- 前置：同一帖子由同一品牌的多个搜索词命中，并重复取得相同命中组合。
- 操作：保存帖子品牌命中关系。
- 期望：不同搜索词分别保留命中证据；同一品牌、搜索词和帖子组合只保存一条关系；搜索词停用或归档后历史关系不删除；按品牌统计帖子时同一帖子只计算一次。
- 关联子功能：必须实现3、10。

### AC-8：原始字段快照脱敏

- 前置：原始字段包含Cookie、Token、密码、手机号、带访问Token的URL和普通帖子ID。
- 操作：保存帖子或评论原始字段快照。
- 期望：敏感键和值被移除或遮盖；普通帖子ID不被误伤；数据库和日志中不存在原始敏感值；脱敏或JSON序列化失败时不保存快照，任务记录结构化错误且不包含原文。
- 关联子功能：必须实现8。

### AC-9：单篇事务和部分成功

- 前置：一个采集任务包含两篇帖子，第二篇在评论或快照写入阶段触发数据库约束错误。
- 操作：执行批量持久化。
- 期望：第一篇帖子及其关联数据完整保存；第二篇本次涉及的帖子、评论、快照和命中关系全部回滚；任务状态为`partial_success`并记录成功数、失败数和脱敏错误摘要；历史成功数据不被删除或清空。
- 关联子功能：必须实现4、6，应该实现4。

### AC-10：任务失败和安全重试

- 前置：任务分别在取得数据前失败、部分写入后失败和从失败任务发起重试。
- 操作：结束任务并创建重试任务。
- 期望：取得数据前失败时状态为`failed`且不推进游标；部分写入后状态为`partial_success`；重试创建新的任务记录并引用原失败任务，原任务状态和错误证据保持不变。
- 关联子功能：必须实现6、9。

### AC-11：品牌级租约锁

- 前置：同一数据来源和品牌同时收到小时任务与手动任务，不同品牌另有一个任务；另准备一条已经过期的锁。
- 操作：并发申请任务锁并模拟持锁进程异常退出。
- 期望：同一品牌只有一个任务取得锁，另一个任务得到明确的并发拒绝结果；不同品牌可以同时取得锁；过期锁能够被新任务原子接管；旧持有者不得释放或续租已经被接管的锁。
- 关联子功能：必须实现7。

### AC-12：采集游标推进

- 前置：一个任务包含成功阶段和失败阶段，并存在旧游标值。
- 操作：分别提交成功阶段和失败阶段的游标更新。
- 期望：成功阶段以原子方式推进游标；失败阶段保持旧值；较旧任务不得覆盖较新游标；游标能够关联最后成功任务和更新时间。
- 关联子功能：必须实现9。

### AC-13：时间、字符集和引用约束

- 前置：写入中文、表情符号、UTC毫秒时间、相同外部ID和被引用记录。
- 操作：保存并读取数据，尝试插入重复业务键和物理删除被引用记录。
- 期望：中文和表情符号无损读取；业务时间使用UTC语义的`DATETIME(3)`；重复业务键被唯一约束阻止或转为幂等更新；物理删除被外键阻止；平台外部ID使用区分大小写的比较规则。
- 关联子功能：必须实现3，应该实现5。

### AC-14：健康检查和连接池

- 前置：数据库配置分别正确、密码错误、目标数据库无权访问和SSL连接不可用。
- 操作：执行健康检查命令。
- 期望：正确配置返回连接成功、目标数据库匹配、MySQL主版本和SSL启用状态；其他情况返回非零退出码和脱敏错误类型；默认连接池上限为5并允许通过环境变量下调或上调到安全范围。
- 关联子功能：应该实现1、3、4。

### AC-15：云MySQL真实迁移验收
