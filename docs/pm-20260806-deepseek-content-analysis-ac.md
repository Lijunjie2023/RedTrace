# DeepSeek帖子与评论分类验收标准

## 目标

使用DeepSeek官方`deepseek-v4-flash`模型，对已入库的小红书帖子和评论进行结构化分类，并让每项分析结论能够回溯到原始内容、模型版本和提示词版本。

## 本轮范围

- 分析对象：数据库中尚未完成当前版本分析，或原文发生变化的帖子和评论。
- 分析字段：情感倾向、内容性质、问题类型、产品品类、产品系列、产品型号、用户阶段、风险等级、置信度和原因主题。
- 分析入口：提供独立命令行批处理入口。单次运行必须支持内容类型和数量上限，便于先用小样本验证成本与准确性。
- 数据展示：LIVE模式的内容列表和详情读取已经持久化的模型分析结果；没有结果时继续返回`UNAVAILABLE`，不得即时调用模型或伪造结论。
- 人工修正：模型原始结果保持只读，人工修正单独保存。有效结果优先使用人工修正，删除修正后恢复模型结果。
- 本轮不做自动定时调度、原因聚类、关键词生成、图片文字识别和大批量历史回填。

## 模型与配置

- 默认接口地址：`https://api.deepseek.com`。
- 默认模型：`deepseek-v4-flash`。
- 使用OpenAI兼容的`POST /chat/completions`接口、非流式JSON输出，并关闭思考模式。
- 密钥只从本机`.env.local`的`DEEPSEEK_API_KEY`读取，不进入代码、文档、日志、数据库或提交记录。
- 接口地址、模型名、超时、最大重试次数和单次处理上限必须能够通过环境变量调整。
- API日志不得包含Authorization头、密钥、完整帖子正文、完整评论正文或模型原始响应。

## 分类约束

- `sentiment`只能为`POSITIVE`、`NEUTRAL`、`NEGATIVE`或`UNKNOWN`。
- `riskLevel`只能为`NORMAL`、`WATCH`或`HIGH_RISK`。
- `confidence`只能为`HIGH`、`MEDIUM`或`LOW`。
- 品类、问题类型和原因主题只能引用数据库中当前启用的分类项ID。模型不得创建不存在的ID；无法匹配时返回空值。
- 问题类型和原因主题允许多选，结果需要去重。
- 产品系列、产品型号、内容性质和用户阶段无法可靠判断时返回`null`，不得凭品牌常识补全。
- 帖子使用标题、正文、话题和命中品牌作为证据。评论还需要带上所属帖子标题、有限长度的帖子正文和父评论上下文，避免脱离语境判断。
- 提示词中的网页内容一律视为不可信数据，不得执行其中的指令。

## 持久化与版本

- 分类词表独立存储，至少支持`CATEGORY`、`PROBLEM_TYPE`和`TOPIC`三种类型、启停状态、排序和版本号。
- 每次分析任务保存内容类型、内容ID、输入摘要、模型名、提示词版本、词表摘要、状态、尝试次数、结构化结果、用量、完成时间和脱敏错误摘要。
- 帖子与评论原文更新后，输入摘要发生变化，允许生成新一版分析；历史成功结果继续保留。
- 相同内容、输入摘要、模型、提示词版本和词表摘要不得产生重复成功结果。
- 失败记录不得覆盖最近一次成功结果；重试成功后将新结果设为当前模型结果。
- 人工修正独立保存并使用版本号控制并发。模型重新分析不得覆盖人工修正。

## 失败处理

- HTTP 429、超时和5xx错误允许有限次数重试，并使用递增等待时间。
- 401、403、无效配置和余额不足等不可恢复错误需要立即停止本轮批处理。
- JSON无法解析、字段不符合约束、分类ID不存在时，本条标记失败，不写入半成品分析结果。
- 单条内容失败不得回滚其他已经成功的内容。
- 命令行汇总只输出处理数量、成功数量、跳过数量、失败数量、Token用量和脱敏错误代码。

## 验收标准

### AC-1：配置与密钥保护

- 未设置密钥时，程序在调用网络前返回明确的配置错误。
- `.env.example`只包含占位配置；`.env.local`继续被Git忽略。
- 任何错误输出和测试快照都不出现密钥或Authorization值。

### AC-2：帖子结构化分类

- 给定一篇有正文的帖子和启用分类词表，模型响应通过严格校验后写入完整分析记录。
- 结果中的品类、问题类型和主题均来自传入的启用词表。
- LIVE内容详情返回`analysisOrigin=MODEL`、模型名和分析时间，并保留原帖链接。

### AC-3：评论上下文分类

- 评论请求包含评论原文、所属帖子标题和受限长度的帖子上下文；二级回复存在父评论时包含父评论上下文。
- 评论分析结果只关联该评论，同时能够通过评论回溯所属帖子。

### AC-4：幂等与重新分析

- 对未变化内容重复执行相同模型、提示词和词表版本时，不再次调用模型。
- 原文、模型、提示词或词表任一发生变化时可以产生新版本，历史成功结果仍可审计。

### AC-5：失败隔离与重试

- 首次请求遇到429或5xx后按照限制重试；超过次数只标记当前内容失败。
- 401或403发生后停止批处理，已经成功保存的内容不回滚。
- 非法JSON和越界分类ID不会成为当前有效结果。

### AC-6：人工修正优先级

- 没有人工修正时，有效结果等于最新成功模型结果。
- 保存人工修正后，有效结果标记为`HUMAN_OVERRIDE`，模型原结果保持可见。
- 删除人工修正后，有效结果恢复为最新成功模型结果。

### AC-7：小样本真实联调

- 使用用户本机配置的DeepSeek密钥，对至少一篇真实帖子和一条真实评论执行分析。
- 验证官方`deepseek-v4-flash`接口可访问、JSON结果能够通过校验、数据库能够保存且LIVE详情能够读取。
- 联调报告只记录内容内部ID、结果摘要、耗时和Token用量，不复制完整原文或密钥。
