# ReadTrace 首页驾驶舱 UI 方案

日期：2026-08-06

## 设计判读

- Purpose：让公司领导、策划和运营在一个屏幕内判断负面舆情是否异常、问题集中在哪里，并进入原帖或评论核对证据。
- Tone：工业化、克制、高密度的风险监测台。
- Constraints：沿用 React 现有信息结构和项目设计变量；桌面端优先；统计必须可追溯；缺失指标不得用推测值替代。
- Differentiation：趋势、问题热榜和用户原话形成从异常到原因再到证据的同屏阅读链路。

## 项目设计语言映射

| 类别 | 项目现状 | 本方案使用方式 |
| --- | --- | --- |
| 样式系统 | 全局 CSS 变量与 BEM 风格类名 | 继续复用，不建立第二套变量 |
| 画布与表面 | `--color-canvas`、`--color-surface`、`--color-surface-raised` | 页面采用近黑画布和两级石墨表面 |
| 业务强调 | `--color-risk`、`--color-positive`、`--color-success`、`--color-warning` | 红色只表示风险，青色表示正向，绿色只表示健康，黄色表示提醒 |
| 文字层级 | `--color-ink-primary`、`--color-ink-secondary`、`--color-ink-tertiary` | 主标题、正文、辅助说明三级对比 |
| 字体 | `--font-display`、`--font-body`、`--font-numeric` | 标题使用阿里妈妈数黑体，正文使用思源黑体体系，数字使用 JetBrains Mono |
| 字号 | `--type-label` 至 `--type-metric` | 风险总量和关键占比使用指标字号，其余遵循现有层级 |
| 间距 | `--space-1` 至 `--space-8` | 采用 4px 基准网格，面板内部以 `--space-4/5` 为主 |
| 圆角 | `--radius-control`、`--radius-panel` | 保持小圆角，避免消费级大圆角卡片感 |
| 阴影与动效 | `--shadow-float`、`--motion-fast/base/enter` | 只用于悬浮提示、聚焦和首屏依次进入 |

## 信息层级

### 第一层级

- 本周负面问题变化：负面总量、较上期变化、每日趋势和异常节点。
- 问题热榜：按证据量排序，显示较上期变化、影响帖子数和评论数。
- 代表性原话：直接展示高风险用户表达，并提供查看原帖或评论的入口。

### 第二层级

- 时间范围、品牌和产品品类筛选。
- 品类负面问题对比：各品类负面数量、占比和主要问题。
- 情感构成：负向、正向、中性和无法判断的真实占比。

### 第三层级

- 数据覆盖率、采集量、延迟、重复率和风险过滤状态。
- 最后更新时间、采集状态和正式数据模式。

## 布局结构

```text
┌──────────┬──────────────────────────────────────────────────────────────┐
│ 品牌与导航 │ 时间范围 / 品牌 / 品类筛选                         日期入口 │
│          ├────────────────────────┬─────────────────┬──────────────────┤
│ 舆情概览 │ 负面问题变化 45%        │ 问题热榜 27%     │ 代表性原话 28%  │
│ 问题分析 │ 趋势图 + 三项摘要       │ 排名与变化       │ 三条证据卡       │
│ 内容明细 ├──────────────────────────────────────────┬──────────────────┤
│ 关键词   │ 品类负面问题对比 72%                       │ 情感构成 28%      │
│ 监控设置 ├─────────────────────────────────────────────────────────────┤
│ 状态入口 │ 数据覆盖与质量横条                                             │
└──────────┴──────────────────────────────────────────────────────────────┘
```

- 设计图采用 1920×1080 桌面画布，左侧栏约占 10%，主区采用 12 列网格。
- 1440px 以下缩窄侧栏；1024px 以下将代表性原话移到第二行；移动端改为底部五项导航并纵向排列面板。
- 首屏不出现独立页面标题大块留白，筛选条和业务面板直接进入工作区，提高信息利用率。

## 组件规格

| 组件 | 类型 | 视觉与状态 | 内容约束 |
| --- | --- | --- | --- |
| 左侧导航 | 复用现有导航并调整视觉 | 当前项使用风险红色底与左侧强调；hover 仅提高表面亮度 | 固定五项，文字不换行 |
| 筛选控件 | 复用 `FilterBar` | 默认石墨底，hover 提高边框对比，disabled 同时降低文字和图标对比 | 近7天、Leader、全部品类为设计示例 |
| 趋势面板 | 现有趋势面板变体 | 红色实线为本期，灰色虚线为上期；异常节点用小型标注 | 最多显示 7 个时间点和 2 个异常说明 |
| 问题热榜 | 现有排行变体 | 前三名使用风险红、警示橙、黄色序号；整行可进入问题证据 | 问题名最多一行，超长省略 |
| 原话证据卡 | 现有 `EvidenceItem` 变体 | 情感和品类标签分离，底部保留互动量与原帖入口 | 原文最多 3 行，不能用关键词替代原话 |
| 品类对比 | 新增首页专属变体 | 五列等宽数据单元加进度条，右侧共用情感环图 | 品类、负面量、较上期、负面占比、主要问题分别展示 |
| 质量横条 | 现有健康状态扩展 | 绿色只表示正常，异常项同时使用图标、文字和颜色 | 仅显示可以验证的质量指标 |

## 交互与动效

- 页面进入：面板按从左到右、从上到下顺序使用 `--motion-enter` 进入，强化阅读顺序。
- 趋势点、热榜行、品类单元和证据卡：hover 使用 `--motion-fast`，只改变表面亮度与边框，不做位移跳动。
- 筛选变化：保留旧数据并显示刷新状态；失败时明确标注为上一次成功结果。
- 图表必须提供文本摘要或数据表；键盘可以聚焦数据点和钻取入口。
- `prefers-reduced-motion` 下关闭非必要动画。

## 反套路与工程自检

- 沿用项目字体和红色风险语义，不引入紫色渐变、玻璃拟态或大圆角 KPI 卡。
- 信息密度高，但通过三层文字对比、统一网格和固定面板间距保持可读性。
- 情感、品类和问题类型继续使用独立字段，不合并为单一标签。
- 热榜、趋势和原话均保留证据钻取入口。
- 错误和风险状态不只依赖颜色，同时使用图标与文字。

## 待决策项

- 参考图包含分品类负面量、数据覆盖率、重复率和延迟等指标；当前接口缺少其中一部分。正式开发时应隐藏缺失项或补充后端统计，不得使用示例值。
- 评论没有独立可验证发布时间。按日期钻取评论需要统一使用父帖发布时间，后端应先明确统计口径。
- 人工修正页面仍需要将内部分类编号替换为名称选择器，本次首页设计不处理该下游页面。

## 给实施 Agent 的说明

- 设计依据来自 `apps/web/src/styles.css`、`layout/app-shell.tsx` 和 `pages/overview.tsx`。
- 实施时继续复用现有变量、`Panel`、`FilterBar`、`EvidenceItem`、`DataHealth` 和图标体系。
- 首页允许新增面板变体，不重命名既有变量，不引入新的 UI 库。
- 所有示意图数字只用于视觉核对；真实页面必须完全由接口返回值驱动。
