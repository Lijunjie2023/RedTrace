# 多关键词API采集开发记录

## 目标

恢复生产环境的API采集凭证和AI分析凭证保存能力，并让一次采集任务支持多个关键词。

## 关键词规则

- 支持中文逗号和英文逗号分隔。
- 自动去除首尾空格、空项和大小写重复项。
- 每个任务最多包含5个关键词，规范化后的完整字段不超过50个字符。
- 帖子上限按每个关键词计算，每个关键词最多10篇。
- 跨关键词命中的相同帖子只采集一次，同时保存该帖子的全部关键词命中关系。
- 没有评论的帖子仍然不进入业务数据库。

## 凭证配置

- 生产环境当前缺少 `CREDENTIAL_ENCRYPTION_KEY_BASE64`，这是凭证无法保存的直接原因。
- 主密钥必须在生产服务器本地生成并写入受控环境文件，不进入命令输出、仓库或日志。
- 已有代码保持保存和解密时强制要求主密钥。

## 验证

- 多关键词解析、去重、数量限制和采集循环需要加入自动化测试。
- 交付前执行全量测试、类型检查和生产构建。
- 上线后使用不含真实凭证的状态检查确认配置已生效，再由用户在页面保存凭证。

## 生产发布结果

- 提交 `6577fd8` 已推送并部署到生产服务器。
- 生产服务器本地生成了32字节随机加密主密钥，受控环境文件保持 `0640 root:readtrace` 权限；密钥未回显、未进入仓库。
- 新前端产物已经发布，线上静态资源包含多关键词提示文案。
- API服务恢复为 `active`，外部HTTPS会话接口返回结构化LIVE响应。
- 自动分析定时器继续保持 `disabled` 和 `inactive`，没有改变既有内存保护策略。
- 发布期间远程构建命令超时，API一度未恢复；确认代码和前端产物完整后，已经单独启动API并完成健康检查。
