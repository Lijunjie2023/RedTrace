# 自动分析实现与部署工作日志

日期：2026-08-07

## 目标

让服务端统一分析待处理的帖子和评论，每30分钟自动触发一次，同时允许管理员在数据管理页面手动触发。

## 本地实现

- 新增统一分析入口，每轮先处理帖子，再处理评论，每类最多处理10条。
- 自动触发和手动触发共用MySQL全局锁，避免同一时间重复调用模型。
- 新增管理员手动触发接口和数据管理页面按钮。
- 新增systemd一次性服务和定时器，开机5分钟后首次触发，之后每30分钟触发。
- 不可恢复的模型错误会停止本轮后续处理；日志只保留数量、Token用量和安全错误码。

## 本地验证

- `npm test`：113项通过，1项因当前Windows环境不允许创建文件符号链接而按预期跳过。
- `npm run typecheck`：通过。
- `npm run build`：通过。
- `git diff --check`：通过。
- Python Playwright及其辅助脚本在当前环境中不可用；改为在部署后通过线上接口、页面资源和服务状态验证运行结果。

## 部署验收项

- 线上安装并验证分析service和timer。
- 手动运行一次分析service，确认安全汇总和退出状态。
- 确认timer处于active，并显示下一次触发时间。
- 确认API、Nginx和线上健康检查恢复正常。
