# ReadTrace Web实现工作日志

日期：2026-08-06

## 本次范围

- 在`apps/web`建立独立React、Vite、TypeScript和React Router应用。
- 实现`/login`、`/overview`、`/insights`、`/content`、`/content/:contentType/:id`、`/brands`、`/data-status`七条路由。
- 主导航只包含概览、原因洞察、内容库、品牌监控和数据状态五项。
- 前端数据统一经过`@readtrace/contracts`运行时schema校验，不读取fixture、数据库模块或API内部实现。
- 按UI方案实现近纸色、石墨色、朱红风险色和青绿成功色的编辑部调查台界面。

## 关键实现

- API客户端使用`/api/v1`，列表分页读取`meta.pagination`，契约错误显示请求编号且不补造业务结论。
- 请求失败时保留上一次成功数据，并提供重新加载操作。
- MOCK模式会触发不可关闭横幅、数据区印章、浏览器标题和导出按钮文案变化。模拟证据不提供原帖跳转。
- 内容详情展示原文、上下文、模型原始结果和人工修正表单。PATCH请求通过`If-Match`发送当前版本。
- 导出端点返回未实现时，只显示明确提示，不生成空文件。
- 品牌页支持新增、编辑、启停和手动更新；版本冲突、重复品牌和运行任务冲突都有明确提示。
- 数据状态页区分正常、部分成功、失败、延迟和汇总状态暂不可用。

## 验证与限制

- 使用仓库现有TypeScript编译器对17个前端TypeScript文件完成无输出语法转译检查，未发现语法错误。
- 未执行`npm install`，也未修改根`package.json`和`package-lock.json`。
- `apps/web/node_modules`当前不存在，因此React、Vite和共享包依赖无法解析，完整typecheck、build和浏览器运行留给依赖安装后的审查阶段。

## 体验审查P1修正

- 内容库移动端列表为每条内容保留“查看详情与修正”入口，并补充上一页、下一页、当前页、总页数和总条数；页码同步到URL的`page`参数。
- 1024至1439宽度下保留主导航中文名称，仅收窄侧栏和字号。
- 移动端表格保留语义化表头，放入局部横向滚动区域，并显示“表格可左右滑动查看完整字段”提示。
- 内容详情的未保存人工修正会拦截应用内链接、返回操作、浏览器后退和关闭或刷新页面，并要求用户确认。
- 导出功能在尚未实现时明确禁用并解释原因，不生成空文件或不完整文件。
- 情感趋势补齐中性数据点，负向、正向和中性分别进入对应筛选结果。
- 原因主题选择与URL的`topicId`双向同步；无效或缺失主题编号会回落到当前列表首项并修正URL。
- 内容库取消无法使用的“全部”范围，只保留帖子和评论；缺少内容类型时首次请求直接按帖子查询并把`contentType=POST`写回URL，类型切换会把页码重置为第一页。
