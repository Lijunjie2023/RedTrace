# Web API后端、共享契约与模拟数据实现记录

日期：2026-08-06

## 本轮完成

- 建立`packages/contracts`，集中定义响应元信息、分页、错误代码、公共枚举、内容、品牌、分类和采集任务运行时契约。
- 建立`fixtures/web-api`，提供以Leader为品牌词的纯模拟数据。模拟作者、正文和ID均有明显标识，不包含真实小红书链接。
- 建立Fastify API，支持模拟登录会话、总览、主题、关键词、内容、品牌、分类和采集任务读取。
- 模拟模式支持品牌新增、品牌版本修改、人工修正及撤销，所有修改只保存在进程内。
- 导出端点固定返回`NOT_IMPLEMENTED`，不会生成空文件或伪造下载地址。
- 建立MySQL只读仓储边界，可以读取现有品牌、帖子、评论和采集任务。分析表尚未建立时，分析类端点返回`DATA_NOT_READY`，不会回退到模拟数据。
- `DATA_MODE=mock`只加载MockRepository；MySQL模块通过mysql模式下的动态导入加载，模拟模式启动不会创建数据库连接。

## 安全边界

- 没有把数据库账号、密码、Cookie、Token或连接地址写入代码、fixture和文档。
- API不记录请求体；日志会脱敏Cookie、Authorization和Set-Cookie头。
- 模拟登录仅供本地联调使用，任何符合字段格式的输入都会创建临时会话；正式管理员认证尚未实现。
- MySQL写操作、真实分析持久化、分类写操作和导出生成仍明确返回未实现状态。

## 2026-08-06审查问题修复

- 统一错误响应的元信息，现在包含`persistence`，Mock错误同时保留fixture版本，能够通过共享错误契约解析。
- 补齐时间、品牌、情感、品类、问题类型、主题、内容性质、风险等级和产品字段等组合筛选解析。Mock内容列表会实际应用这些字段；LIVE模式无法映射到现有采集表的分析筛选会返回`DATA_NOT_READY`。
- LIVE帖子列表支持参数化的时间、品牌和关键词筛选；评论缺少可信发布时间时会明确拒绝时间筛选。
- LIVE混合帖子与评论列表要求显式提供`contentType`，避免分别分页后合并导致遗漏或重复。
- Mock人工修正会保留模型基线，撤销时恢复完整基线字段并递增版本。
- 原始证据只接受`xiaohongshu.com`及其子域名的HTTPS链接，并必须允许打开；模拟证据禁止携带可打开链接。
- Mock登录凭据改为环境配置，比较过程使用SHA-256定长摘要和常量时间比较；LIVE登录仍返回`DATA_NOT_READY`。

## 2026-08-06增量复审修复

- 总览端点现在校验全部查询参数。Mock无法按时间或品牌重新计算总览时返回`DATA_NOT_READY`，不会返回未筛选的完整数据。
- 主题和关键词会真实应用情感、主题筛选；关键词fixture补充主题关联。其余无法由当前fixture支持的筛选返回`DATA_NOT_READY`。
- 每个列表端点都声明允许的筛选字段，已经解析但不属于该端点的字段返回`VALIDATION_ERROR`，不再静默忽略。
- 内容列表共享查询契约与服务端均要求显式提供`contentType=POST|COMMENT`，保证LIVE分页使用单一、稳定的数据序列。
