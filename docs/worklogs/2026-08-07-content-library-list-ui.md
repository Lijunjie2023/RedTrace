# 内容明细列表化改造

## 目标

把原有“列表加右侧预览”的内容明细页改成帖子库、评论库两套全宽列表，方便运营人员连续浏览和翻页核对证据。

## 已确认范围

- 帖子库与评论库使用标签切换，不混合分页。
- 每页固定展示10条，不提供每页条数切换。
- 保留现有筛选条件与评论日期限制。
- 列表展示内容摘要、情感与风险、互动量、发布时间和证据操作。
- 增加主导航中的“内容明细”入口。
- 移动端底部导航保留四个主要页面，隐藏低频的“数据管理”，避免概览页加上退出入口后超过五项。

## 实现说明

- 前端请求始终写入`pageSize=10`，已有其他分页大小的链接会自动归一为10。
- 表头与数据行统一使用同一张语义化表格和同一组列宽类，避免独立网格造成错位。
- 页脚展示总数、固定每页条数、页码、省略号以及上一页和下一页。
- 评论没有可信发布时间，切换评论库时继续清除日期条件并展示说明。
- 当前接口只提供品牌编号和品类编号，没有稳定的展示名称，因此本次没有新增无法可靠展示的品牌／品类列。

## 验证清单

- TypeScript与Vite生产构建通过。
- 自动化测试共121项，120项通过，1项因当前Windows环境不允许创建测试所需的符号链接而跳过。
- 浏览器使用项目模拟数据验证帖子库固定显示10行、评论库切换、页码跳转和`pageSize=10`请求参数，控制台没有错误。
- 在1440像素和1920像素宽度下测量五列表头与首行单元格，横向中心偏差均为0像素。
- 在375像素宽度下，页面文档宽度与视口宽度均为375像素，没有整页横向溢出；移动端显示四个主要导航入口。
- 本地API进程受当前Node运行时`uv_os_get_passwd ENOMEM`系统错误影响未能启动，因此浏览器验收通过请求拦截使用项目自带模拟数据完成，没有覆盖真实登录和线上接口链路。
