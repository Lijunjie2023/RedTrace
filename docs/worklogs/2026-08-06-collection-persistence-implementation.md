# 采集持久化基础层实现记录

日期：2026-08-06

## 实现范围

完成MySQL配置校验、脱敏健康检查、版本化迁移执行器、迁移状态检查和首个采集表结构迁移。本工作包没有连接正式云数据库，也没有实现帖子写入服务、任务调度、分析或页面。

## 关键决定

- 使用独立环境字段而不是数据库连接串，避免密码中的特殊字符被URL解析改变。
- 连接池默认上限为5，允许在1到10之间调整，以适配1核、2GB内存的MySQL实例。
- 迁移按照四位版本号顺序执行，用SHA-256校验历史文件，只允许向前升级。
- SQL文件使用显式语句分隔标记，支持触发器定义且不启用多语句连接选项。
- 外部帖子ID和评论ID采用`ascii_bin`，保证大小写敏感；中文内容采用`utf8mb4`。
- 归档或未启用品牌由数据库触发器阻止创建新采集任务。
- 所有外键采用限制删除，迁移工具不提供回滚、删表或清库功能。
- MySQL密码保持dotenv解析后的原始值，不执行`trim`或其他改写；普通配置字段继续去除首尾空白。
- 连接池通过mysql2的底层`connection`事件为每个新连接设置UTC会话时区，健康检查在同一连接内验证结果。
- 迁移状态命令只读；迁移表不存在时返回全部本地迁移待执行，不创建任何表。
- 已应用迁移必须构成本地迁移列表的连续前缀，缺号、跳号或内容变化都会停止执行。

## 验证边界

本次只执行本地静态检查和既有测试。正式云MySQL健康检查及迁移由主控使用本地`.env.local`验收。
