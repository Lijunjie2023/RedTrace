# JustOneAPI 小红书数据采集能力评估

- 日期：2026-08-06
- 任务：评估 JustOneAPI 小红书接口能否支撑 ReadTrace 第一版数据采集。
- 结论：接口组合能够覆盖第一版采集主链路，适合进入小规模验证；仅凭公开文档，暂时不能作为正式监控的数据源定案。

## 第一版所需链路与接口

1. 使用“笔记搜索 V4”按品牌词、产品词和问题词发现相关笔记，优先采用时间降序，并按页持续获取。
2. 使用“笔记详情 V1”补齐原文、作者、发布时间、互动量和原帖标识等信息。
3. 使用“笔记评论 V2”按游标获取评论，默认采用最新排序；获取失败时按文档建议改用普通排序重试。
4. 使用“评论回复 V2”获取二级回复，保留评论层级关系。
5. 如需监控品牌官方账号或重点账号，使用“用户搜索 V2”和“用户发布笔记 V4”作为补充入口。

## 已确认的能力

- 笔记搜索 V4 支持关键词、分页、时间降序、评论数降序、收藏数降序、笔记类型和发布时间范围过滤。
- 笔记详情可以通过笔记 ID 或探索链接获取。
- 评论支持游标分页，以及最新、普通、点赞数三种排序。
- 评论回复支持按笔记 ID、评论 ID 和游标分页。
- 接口提供业务错误码，可区分采集失败、限流、每日配额、权限不足和余额不足。

## 公开文档无法确认的关键事项

- OpenAPI 中成功响应的 `data` 没有字段结构定义，无法确认标题、正文、作者、发布时间、更新时间、原帖链接、评论正文、评论时间、评论作者、互动量等字段是否稳定存在。
- 文档没有说明关键词搜索结果是否完整，也没有披露最大可翻页数、单页数量、历史覆盖深度、重复或漏采规律。
- 时间过滤仅提供一天、一周、半年和不限，不能直接按任意起止时间查询。
- 没有删除状态、编辑历史或“自上次更新时间后变化”的专用接口，增量更新需要定时重查和本地去重。
- 文档没有给出服务可用性承诺、数据延迟承诺和单接口固定并发上限。
- 价格需要登录后台查看，现阶段无法估算完整评论采集的月度成本。
- 文档没有提供平台授权、个人信息处理、数据留存和商业使用边界说明，需要单独完成合规审查。

## 建议的验证门槛

先购买或使用免费额度做 3 至 7 天验证，不进入正式开发：

- 准备 10 至 20 个品牌词、产品词和已知问题词。
- 每个词验证时间降序分页，记录最大翻页深度、重复率、空页率、超时率和失败率。
- 抽取至少 100 篇笔记，核对搜索结果与详情字段是否能够稳定映射。
- 抽取至少 30 篇评论较多的笔记，完整翻页评论和二级回复，核对总数差异、游标终止条件和排序差异。
- 隔 24 小时重复采集同一批笔记，验证新增评论、互动量变化、正文编辑和删除状态能否识别。
- 手工在小红书搜索结果中抽样对照，估算 API 的漏采率和时间延迟。
- 根据真实调用次数核算“每个关键词每天成本”和“每篇笔记完整评论成本”。

## 决策标准

只有在字段稳定、证据链接可回溯、漏采率与延迟可接受、评论分页能够闭合、成本可控、合规边界明确后，才能将其确定为第一版主数据源。若覆盖率不稳定，可保留为发现层数据源，并为第二数据源或人工补录预留接口。
