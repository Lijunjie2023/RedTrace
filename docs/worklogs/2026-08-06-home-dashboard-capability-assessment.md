# 首页驾驶舱改造能力评估

日期：2026-08-06

## 评估范围

针对首页驾驶舱标注项，核对现有 MySQL 表结构、接口合同、查询实现和前端筛选逻辑，不修改代码。

## 总体结论

- 现有数据库能够支撑多品牌、品类、问题主题、原始帖子与评论、AI 分类状态等核心能力，不需要为了本轮首页改造重建业务表。
- 当前 `/overview` 只接受日期和品牌筛选。品类筛选、点击品类后刷新整页、问题热榜与右侧原话联动，需要扩展接口和查询逻辑。
- “数据管理”所需的帖子总数、评论总数、AI 已分类数量可以从现有表统计，但当前没有对应接口和页面。
- 参考图中的上周同期、问题增长率、分品类负面占比、覆盖率、重复率和风险过滤数并非全部具备可靠口径，不能直接使用示意值。

## 标注项结论

| 标注项 | 数据库 | 当前接口与前端 | 结论 |
| --- | --- | --- | --- |
| 删除趋势图说明文字 | 不涉及数据库 | 前端可直接处理 | 可以立即实现 |
| 点击问题热榜联动代表性原话 | `analysis_topics`、`analysis_problem_types`、帖子与评论关系能够支撑 | 已有主题证据接口，但不能同时保留首页日期、品牌等完整筛选 | 需要扩展证据查询或首页响应 |
| 暂不开发问题分析、内容明细页面 | 不涉及数据库 | 可以隐藏导航；证据详情深链建议保留 | 可以立即实现 |
| 品牌多选 | `brands`、`brand_post_matches` 能够支撑；评论可以通过所属帖子关联品牌 | 服务端已经支持逗号分隔的多个 `brandIds`，前端仍是单选 | 主要是前端改造 |
| 品类选择 | `classification_items` 和 `analysis_records.category_id` 能够支撑 | 分类列表接口可提供品类，但 `/overview` 拒绝 `categoryIds` | 需要扩展首页接口 |
| 点击品类卡片筛选首页 | 分类字段能够支撑 | 内容列表支持 `categoryIds`，首页不支持 | 需要扩展首页接口并同步 URL 状态 |
| 新增数据管理 | `posts`、`comments`、`analysis_records` 能够统计总量和 AI 分类量 | 当前没有汇总接口和数据管理页面 | 需要新增只读统计接口和页面 |

## 统计口径建议

- 多品牌采用“任一品牌命中”的并集逻辑，同一帖子命中多个已选品牌时只统计一次。
- AI 已分类数量不能直接统计 `analysis_records` 行数，因为重试和重新分析会产生多条记录。应按帖子或评论去重，统计存在成功分析结果的内容数量。
- AI 分类率分别展示帖子和评论，再提供总分类率，避免总数掩盖评论未分类问题。
- 人工修正不计入“AI 已分类”，可以另设“人工已修正”数量。
- 品类筛选只统计已经获得有效品类结果的内容；未分类内容是否提供“未分类”选项需要产品确认。
- 评论没有独立标准发布时间。首页趋势目前使用所属帖子的发布时间；任何日期钻取都必须沿用同一口径。

## 参考图中暂不具备的能力

- `/overview` 当前没有上周同期序列，无法直接显示灰色同期折线。
- 问题热榜的 `changeRatio` 在 MySQL 实现中固定为 `null`，无法显示可靠的增长率。
- 当前问题热榜只返回证据总数，没有分别返回影响帖子数和评论数。
- 当前品类排行只返回内容总量，没有分品类负面量、负面占比、较上期变化和主要问题。
- 数据覆盖率缺少明确的应采集总量分母。
- 数据库依靠唯一键去重，但没有保存“发现多少重复数据”的独立计数，因此不能直接展示重复率。
- 没有明确的风险数据过滤事件台账，无法可靠展示已拦截数量。

## 其他注意事项

- 问题热榜联动建议把选中主题写入 URL，刷新和分享后仍然保持同一问题和筛选条件。
- 右侧原话应明确显示帖子或评论，并保留原始证据入口。评论表没有独立 `source_url`，当前通常只能打开所属帖子；如果要求精确定位原评论，需要补充可用的评论定位链接或平台锚点。
- 隐藏“问题分析”和“内容明细”导航时，不建议删除证据详情路由，否则首页无法完成证据回溯闭环。
- 多品牌下拉需要搜索、全选和已选数量提示；当前品牌接口单页最多 50 条，品牌数量增长后需要分页或远程搜索。
- 品类来源于 AI 分析和人工修正，不是帖子原始字段。筛选结果需要明确是否采用人工修正后的有效结果，推荐继续使用有效结果。
- RDS 规格为 1 核，首页不要为每个面板各发一轮重复聚合。建议一个首页聚合请求返回同一筛选口径下的全部面板数据，并对高频统计做短时缓存。

## 推荐实施顺序

1. 确认多品牌采用并集逻辑，以及品类筛选是否包含“未分类”。
2. 扩展首页查询合同，支持 `brandIds`、`categoryIds` 和选中主题。
3. 扩展首页响应，增加同期趋势、问题帖子/评论数、分品类负面指标；没有可靠口径的指标继续隐藏。
4. 新增数据管理汇总接口，返回帖子、评论、AI 已分类和人工修正数量。
5. 最后改造首页交互和侧边栏，保证所有筛选写入 URL 并可恢复。
