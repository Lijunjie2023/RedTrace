# 小红书采集探针实现记录

日期：2026-08-06

## 范围

实现独立TypeScript命令行探针，用持久化Playwright浏览器目录验证`Leader`搜索、帖子详情、互动数据、首批评论和回复关系。没有连接MySQL，也没有实现调度、分析或业务页面。

## 关键约束

- 浏览器始终可见，首次登录由用户亲自完成。
- 一次运行最多读取20条搜索结果和3篇详情，详情访问间隔不少于2秒。
- 只监听并读取页面与JSON响应，不执行任何互动或发布操作。
- Cookie、Token、手机号和验证信息不会写入JSON输出。
- 页面要求验证码或出现访问限制时停止任务，不尝试绕过。
- 同一浏览器目录同时只允许一个探针进程使用。
- 搜索结果同时兼容`/search_result/<帖子ID>`、`/explore/<帖子ID>`和`/discovery/item/<帖子ID>`三种链接形式。
- 页面详情优先补读`window.__INITIAL_STATE__`，解析过程只使用字符串处理和`JSON.parse`，不会执行页面脚本。
- 输出使用不含临时访问Token的规范帖子链接；带参数的地址只在当前进程内用于页面导航。
- 评论解析兼容真实接口的`id`、`user_info`、`sub_comments`和`target_comment.id`，并按照嵌套上下文保留父子关系。
- 帖子显示存在评论却没有解析到评论时，任务记录评论阶段结构错误并保留脱敏后的评论响应快照。
- 所有已经开始处理的JSON响应会在字段提取前等待完成，避免异步响应与解析过程发生竞态。
- 时间冲突只比较可解析的绝对时间；相对时间继续作为原始证据保留。
- 锁文件中的进程已经退出时会清理陈旧锁，最终JSON写入失败时会尝试另存报告。
- 页面状态按照“需要登录、安全验证、访问限制”的顺序分类；手机号登录页中的“获取验证码”不会再被误判为安全验证。
- 首次打开登录页后等待页面稳定约2秒再判断状态，登录等待期间继续使用相同分类规则。
- 浏览器上下文内的数据读取改用纯字符串脚本，避免TypeScript转换产生的辅助符号在页面中不存在。
- 搜索结果先按照帖子ID合并封面和标题链接，选择标题、卡片正文和行信息更完整的候选，再执行唯一帖子数量上限。
- 详情不再通过带参数地址直接导航，而是在搜索结果页按照帖子ID重新定位可见链接并执行真实点击。
- 点击后的详情同时支持当前页面和新标签页；每篇读取结束后关闭新标签页或返回原搜索结果，再重新定位下一篇。
- 点击没有引起地址或详情内容变化时记录`structure_changed`，不会再自动访问详情地址兜底。
- 同一帖子ID出现多个结构化记录时按照帖子特征评分，评论中的`note_id`不会覆盖真正的帖子卡片。
- 缺少帖子状态数据时，标题、正文、作者和图片优先使用JSON-LD，再使用搜索结果，最后才读取不可靠的DOM字段。
- DOM发布时间只接受带“编辑于”或“发布于”的明确上下文；全页通用`.count`不再作为互动数据来源。
- `tagList`缺失时从正文的`#话题名[话题]#`标记补取话题；正文也没有话题时继续保留`null`。
- 手机号脱敏要求号码两侧不是ASCII字母或数字，避免破坏帖子ID和评论ID中的数字片段。

## 验证边界

本次由编码子任务完成实现和静态检查。真实登录状态、页面结构兼容性以及端到端字段覆盖由主控执行验收。

## 真实端到端验收

使用独立持久化Chromium目录完成登录后，以`Leader统帅`为关键词执行低频验证，限制为10篇搜索结果和1篇详情。

最终有效运行目录：`artifacts/xhs-probe/20260806034509/`

取得结果：

- 搜索页读取到21篇唯一帖子，探针按照上限保留10篇标准化结果候选，其中3篇判定为Leader统帅家电相关。
- 读取1篇Leader统帅三筒洗衣机帖子，取得正确标题、完整正文、作者、地区、发布时间、更新时间、6张图片和规范原始链接。
- 取得帖子点赞数11、收藏数3、评论数34和分享数13。
- 取得首批18条评论，其中8条保留所属一级评论ID；评论ID、正文、作者、时间、地区和点赞字段均可读取。
- 输出保留页面展示时间、JSON-LD时间和页面状态时间；本样本存在时间冲突标记，后续统计不得直接信任JSON-LD时间。
- 最终运行中的唯一字段缺口为结构化话题列表。实现已根据真实正文格式增加`#话题名[话题]#`回填，并由测试覆盖。
- 发现手机号脱敏规则可能误伤平台ID后，已收紧边界条件并增加回归测试。

验收结论：小红书真实数据链路具备继续开发的基础。搜索、帖子正文、互动数据、评论和回复关系均已通过真实账号验证。评论仅验证首批已加载数据，全量翻页、小时级持续运行和账号长期风险仍需后续单独验证。
