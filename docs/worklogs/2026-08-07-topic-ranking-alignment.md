# 问题热榜列对齐修复

## 问题原因

热榜表头和数据行原先分别定义网格。数据列表出现纵向滚动条后，表头与数据行获得的可用宽度不同；同时按钮使用自动宽度时存在收缩计算差异，导致两套相同列值仍然发生横向错位。

## 修复方式

- 新增统一的`topic-ranking-table`纵向滚动容器，表头和数据列表处于同一个滚动口中。
- 表头和数据行共同使用`topic-ranking-grid`，列宽只由`--topic-ranking-columns`定义一次。
- 每个表头和数据单元使用明确的语义类名，排名、较上期、影响帖子、评论和箭头居中，问题名称左对齐并支持省略号。
- 表头在容器内部吸顶，滚动十条榜单时仍能查看列含义。
- 数据行按钮和内部网格明确占满统一滚动容器的可用宽度，避免按钮按照内容宽度收缩后造成列中心偏移。
- 数据列表项使用网格布局拉伸按钮，按钮宽度由滚动口的实际可用空间决定，不再使用会按照滚动前包含块计算的百分比宽度，从而消除纵向滚动条出现后的几像素横向溢出。
- 箭头列轨道宽度与1rem图标保持一致，避免图标超出原0.75rem轨道后把滚动宽度撑大4px。
- 排名前三分别使用红色、橙色和黄色圆角方框，第四名起恢复普通数字样式。

## 保留行为

- 热榜继续按照证据数量降序展示，最多十条。
- 点击任意数据行仍会联动右侧代表性原话。
- 面板宽度继续由响应式网格分配，不设置固定宽度，也不引入横向滚动。

- TypeScript类型检查与Web生产构建。
