# 首页品类内容对比与业务词表

## 目标

- 首页品类内容按照冰箱、洗衣机、空调、水联网、厨电、彩电、其他的业务顺序展示。
- 首页最多展示六张品类卡片，桌面端保持单行排列。
- 数据库品类词表统一补齐七项，同时保留已有分析记录的分类关联。

## 前端策略

- 前端只维护业务显示顺序，品类ID和内容数量继续来自接口，不把数据库ID写死在页面中。
- 接口返回的未知品类排在七项业务品类之后，便于后续扩展时仍能安全展示。
- 桌面端根据实际品类数量生成最多六个等宽列；小屏幕继续保持单行，通过品类区域右侧自身横向滚动查看，不会推动整个页面产生横向滚动，也不会为缺少的品类预留空列。
- 品类名称保持单行，避免卡片标题高度不一致。
- 品类区域左侧固定显示品类、当前内容量、相对量级、负面占比和主要问题五项标签，右侧每个品类列只展示对应数据，避免在每张卡片中重复指标名称。
- 左侧标签和右侧数据列复用同一组网格行高，保证六个品类的数据严格横向对齐；中小屏只滚动右侧数据列，标签栏保持可见。
- 当前接口只有内容量和相对量级数据，负面占比与主要问题继续明确显示“待统计”，没有推算或补造数据。
- 品类区域改为纯展示，不再承担点击筛选；筛选操作统一保留在页面顶部的产品品类筛选器中。
- 顶部筛选仍然采用修改条件后点击“查询”统一提交的方式，但不再额外显示“筛选条件尚未查询”提示，减少筛选栏中的视觉干扰。

## 迁移兼容

- `water_heater`继续使用原有记录和ID，只把显示名称安全更新为“水联网”，因此已有`analysis_records.category_id`关联不会变化。
- 彩电与其他通过幂等插入补充；七项品类均更新为启用状态和固定排序值。
- 迁移只使用`UPDATE`与`INSERT ... ON DUPLICATE KEY UPDATE`，没有删除、清空或重建分类记录。
