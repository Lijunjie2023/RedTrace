# 数据采集页面恢复记录

## 现象

生产环境的数据采集页面显示“数据服务暂时不可用”，无法进入凭证设置和任务列表。

## 根因

页面首次加载会读取凭证配置状态。该操作只需要查询数据库中的配置摘要，但服务端错误地提前初始化了凭证加密器。因此，只要生产环境尚未配置 `CREDENTIAL_ENCRYPTION_KEY_BASE64`，连不涉及密钥明文的只读状态接口也会返回 503，进而触发整页错误状态。

## 修复

- 凭证摘要查询不再依赖加密主密钥。
- 保存凭证和读取凭证原值时仍然强制要求加密主密钥，不降低安全要求。
- 增加回归测试，确保只读凭证状态接口不会再次初始化加密器。

## 验证要求

- 执行采集控制台专项测试、全量测试、类型检查和生产构建。
- 部署后验证登录会话和凭证状态接口返回结构化成功响应。
- 生产环境仍需配置加密主密钥后，才能保存 JustOneAPI Token 或 DeepSeek 密钥。

## 生产发布结果

- 修复提交 `0a290b8` 已推送并随目标提交 `a481e15` 更新到生产仓库。
- `readtrace-api.service` 重启后为 `active`，API 继续只监听 `127.0.0.1:3100`。
- `/api/v1/session` 返回结构化 LIVE 模式响应，Nginx 的 443 和 8443 监听保持正常。
- 自动分析定时器继续保持关闭，没有改变既有内存保护策略。
- 生产环境检查确认 `CREDENTIAL_ENCRYPTION_KEY_BASE64` 尚未配置。页面只读状态已经恢复，但保存新凭证前仍需由用户明确授权生成或安装生产主密钥。
