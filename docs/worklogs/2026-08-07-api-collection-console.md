# API 数据采集控制台开发记录

## 目标

增加可由管理员配置 JustOneAPI Token 和 DeepSeek 密钥的数据采集入口，支持启动、停止和查看采集进度，并继续遵守“没有评论的帖子不进入业务数据库”的规则。

## 本次实现

- 新增数据采集页面和侧边栏入口。
- 新增凭证状态、保存和删除接口；凭证使用 AES-256-GCM 加密后保存，接口只返回配置状态和末四位。
- 新增 API 采集任务，支持关键词、品牌和最多十篇帖子的小批量参数。
- 新增协作式停止能力；外部请求完成后停止后续步骤。
- 持久化展示获取帖子、获取评论、入库帖子、入库评论、无评论跳过和失败数量。
- 帖子至少取得一条评论后才会进入业务数据库。
- 页面保存的 DeepSeek 密钥同时供手动分析和每三十分钟自动分析使用，并保留环境变量兼容路径。
- 新增数据库迁移 `0005_api_collection_console.sql`。

## 安全边界

- 真实 Token 和密钥不写入代码、日志、文档或 Git。
- 服务端需要单独配置 `CREDENTIAL_ENCRYPTION_KEY_BASE64`，它必须是 32 字节随机值的 Base64 编码。
- 删除正在被采集或分析任务使用的凭证会被拒绝。
- JustOneAPI 请求失败时只记录安全错误码，不记录请求凭证和采集正文。

## 2026-08-07 审查修复

- API服务建立数据库连接后、开始接收请求前，会把上一个进程遗留的API控制台`queued`和`running`任务收敛为`failed`，把`stopping`任务收敛为`stopped`。收敛范围通过API任务具有关键词和帖子上限这两个字段来限定，不影响其他采集任务；失败任务只记录安全错误码`collection_process_restarted`和固定说明，不记录凭证或采集正文。
- 新任务在从`queued`切换到`running`之前发生异常时，会通过专用失败收敛方法结束任务，避免任务长期占用“正在采集”状态。
- 评论采集现在读取JustOneAPI响应中的`has_more`和`cursor`继续分页；单篇帖子最多读取20页、保留1000条评论，并对重复或缺失游标进行保护。
- 评论分页会在每一页响应结束后检查停止请求；收到停止请求时不再获取下一页，当前页已经取得的评论仍按正常流程记录并保存，随后任务收敛为`stopped`，不会被记为截断或采集失败。
- 如果接口仍有后续页面但触发页数、评论数或游标保护，任务会使用`comment_collection_truncated`结束为部分成功或失败，页面展示的计数仅代表实际获取和保存的数据，不表示评论已经完整采集。
