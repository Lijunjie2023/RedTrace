# 参考图结构化概览改造

日期：2026-08-06

## 目标

在现有暗色界面基础上，将舆情概览调整为参考图的阅读结构，同时继续使用正式 API 字段，不生成示例数字或缺失指标。

## 实现范围

- 左侧导航调整为舆情概览、问题分析、内容明细、关键词和监控设置；数据状态保留为侧栏底部入口。
- 新增 `/keywords` 路由，复用现有洞察数据与证据能力，并将关键词台账放在首要位置。
- 概览顶部保留日期与品牌筛选。品类筛选因概览接口尚未接受 `categoryIds`，以禁用状态明确标注“待统计接口接入”，没有伪造筛选结果。
- 首行保持“负面趋势、问题热榜、代表性原话”三栏结构；趋势点和证据继续进入内容详情或原始证据链路。
- 第二行重构为品类内容与问题对比、情感构成。品类模块只展示合同提供的内容量，并说明负面分品类数量尚未提供。
- 情感构成只在趋势汇总负面占比与总览负面占比误差不超过一个百分点时显示；口径不一致时显示专业说明，不拼装误导性占比图。
- 底部数据覆盖与质量只展示帖子评论总量、高风险证据入口数、采集健康状态和最后成功时间。
- 新布局补充 1440、1024 和 767 像素以下的响应式规则，移动端保持五项底部导航。

## 设计约束

- Purpose：帮助管理者从负面变化进入问题，再回到帖子或评论证据。
- Tone：高密度、克制的工业监测台。
- Constraints：React、现有共享合同、无新增图表依赖、键盘可操作、移动端可读。
- Differentiation：趋势、问题和原话同屏，所有统计都明确其真实口径。
- 继续使用项目 CSS 色彩、字体、间距、圆角、阴影和动效变量；没有引入紫色渐变、玻璃拟态、等宽指标卡或不可验证数据。

## 验证

- `npm run build --workspace @readtrace/web` 通过，包含 TypeScript 项目构建和 Vite 生产构建。
- `git diff --check` 通过。
- 未修改后端、测试、密钥、JustOneAPI 采集文件，也没有执行提交、推送或部署。

## 未覆盖

- 概览接口需要支持 `categoryIds` 后，才能启用品类筛选。
- 接口需要返回分品类负面数与数据质量指标后，才能展示品类负面占比、覆盖率、重复率和延迟时长。
- 人工修正表单仍可能暴露内部分类编号，需要后续将分类名称选择器与分类配置接口完整关联。

## 复审修正

- 问题热榜进入问题分析时保留当前日期和品牌条件，并追加主题条件。
- 概览进入内容明细时显式选择帖子；帖子和评论切换继续保留品牌、情感、品类和问题条件。由于评论没有可验证发布时间，切换评论时清除日期条件并在页面说明。
- 情感构成同时核对趋势总量、帖子评论总量和负面占比；任一计数缺失或不一致时不宣称口径一致。
- 高风险证据数量改为“页面高风险样本”，明确只是当前页展示数量。
- 中等屏幕的采集状态入口保持可见、可聚焦；移动端在顶部提供数据状态入口。
- 关键词页面不再请求或依赖主题列表，也不会自动写入主题编号；关键词可以独立进入对应内容。
- 页面文案移除了实现层术语，热榜变化比例补充“较上期”口径，尚未采集状态不再描述调度频率。
- 内容明细继续使用“帖子 / 评论”两类独立分页，避免前端合并两套分页结果导致排序、总数和翻页口径失真。概览及关键词下钻明确进入帖子视图，评论可以在内容明细中切换查看。
- 跨帖子与评论的统一分页，以及按照父帖发布时间筛选评论，需要后端提供统一查询与明确的日期口径，留待后续开发。本轮评论视图继续隐藏日期筛选，避免发送后端不支持的参数。
- 数据质量区的高风险样本数量与页面实际渲染的四条上限保持一致。
