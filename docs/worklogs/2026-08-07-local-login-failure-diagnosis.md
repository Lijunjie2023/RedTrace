# 本地前端登录失败诊断

日期：2026-08-07

## 诊断范围

- 只读检查本地Vite代理、前端登录请求、API认证实现、会话Cookie和本地运行状态。
- 没有读取或输出账号、密码、Token、Cookie和数据库连接信息的明文。
- 没有重置账号密码，没有修改业务代码、运行配置或服务状态。

## 复现与证据

- 本地前端监听在`127.0.0.1:4173`。
- 本机API默认端口`3100`没有服务监听。
- 通过本地前端访问`GET /api/v1/session`返回`500 text/plain`。
- 使用专门构造的无效测试凭据访问`POST /api/v1/session`同样返回`500 text/plain`，没有返回`Set-Cookie`。
- API认证实现中，真实凭据错误会返回状态码401和结构化错误码`AUTH_FAILED`。因此当前500发生在请求抵达API认证逻辑之前。
- Vite代理配置在没有读取到`READTRACE_API_PROXY_TARGET`时回退到`http://127.0.0.1:3100`；当前受检环境没有可供该代理连接的本机API服务。
- 前端请求已经使用同源`/api/v1`路径和`credentials: include`。当前故障发生在代理连接阶段，CORS和会话Cookie不是本次登录提交失败的直接原因。
- 登录页捕获异常后，无论是凭据错误、代理错误还是网络错误，都显示同一条账号或密码错误提示，导致用户看到的文案与实际故障不一致。

## 根本原因

### 第一层：运行配置没有形成有效代理链路

本地前端的API代理目标没有实际生效，运行时回退到没有服务监听的本机3100端口。登录请求因此由Vite代理直接返回500，没有到达线上API，更没有进行账号密码校验。

如果后续配置的线上地址使用自签名HTTPS证书，还需要单独核对开发代理的证书校验设置；本次诊断尚未配置目标，也没有据此认定存在证书问题。

### 第二层：交付验证和错误呈现均不完整

先前交付只验证了页面显示、自动化测试和构建，没有执行完整的登录会话链路验证，却宣称本地前端继续使用线上接口。与此同时，登录页的统一错误文案把代理故障伪装成凭据错误，使配置问题更难被及时发现。

## Cookie与跨域判断

- 线上数据模式使用`__Host-readtrace_session`，并设置`HttpOnly`、`Secure`、`SameSite=Strict`和根路径。
- 本地前端通过同源`/api`代理发起请求，前端也包含凭据，因此不需要浏览器直接跨域访问线上API。
- 当前登录POST尚未到达API，未产生Cookie。只有代理恢复后，才能继续验证浏览器是否接收Cookie，以及紧接着调用`GET /api/v1/session`能否保持已登录状态。

## 建议的最小修复与验证

1. 明确Vite读取代理配置的目录，确保线上API代理目标在实际启动进程中生效，然后重启本地前端。
2. 先验证本地代理下的会话接口返回API约定的结构化响应，不再返回Vite产生的纯文本500。
3. 由用户在浏览器中输入管理员凭据，验证登录POST成功设置Cookie，并立即验证会话GET返回已登录。
4. 将登录页的凭据错误、服务连接失败和响应格式错误分别展示，避免再次误导用户。
5. 若线上HTTPS使用自签名证书，再根据实际证据调整仅用于本地开发代理的证书校验设置。

## 后续远端诊断安全事件

- 在线上运维诊断中，PowerShell双引号字符串错误解析了SSH远端awk命令中的`$1`，导致数据库旧密码值意外进入内部工具输出。本日志不记录该值。
- 该旧密码已经失去安全性，必须轮换且不得恢复使用。
- 线上旧配置备份当前仅允许root读取，不得下载、展示或复制其正文。
- 原运行时规则要求管理员密码至少16位，导致用户现有密码无法通过配置校验；该规则现已调整为至少8位且只校验长度。
- 服务恢复前只能检查键名是否存在、密码长度是否合规和服务状态，不得再次读取或回显任何环境变量值。

## 本地仓库修复

- Vite开发配置改为固定从仓库根目录加载`.env.local`，避免通过npm workspace启动时误从`apps/web`目录读取配置。
- `.env.example`补充非敏感的本地代理变量示例，真实线上地址继续只保存在被Git忽略的`.env.local`中。
- 登录页只在API明确返回`AUTH_FAILED`时提示账号或密码不正确；代理连接失败、服务端异常和响应合同异常分别显示服务故障提示。
- 登录错误提示改为渲染实际分类结果，不再使用写死的凭据错误文案覆盖真实故障。
- 本次仅修改本地仓库，未读取或输出真实凭据，也未启动、重启或部署任何服务。

- 校验只判断字符数量，不要求必须包含大小写字母、数字或特殊字符。
