# 小红书真实数据采集验证验收标准

参考需求文档：`tasks/prd-xiaohongshu-public-opinion-v1.md`

## 范围

本阶段只验证真实数据链路，不连接MySQL，不实现定时任务、自动分析和业务页面。验证关键词为`Leader`，并使用`统帅、海尔、洗衣机、空调`等词辅助判断品牌相关性。

## 实体生命周期

### 登录会话

未建立 → 等待用户登录 → 可用 → 失效 → 等待重新登录

- 会话只保存在本地持久化浏览器目录中，该目录不得进入Git。
- 登录失效时停止采集并输出明确状态，不删除已经生成的结果。

### 验证任务

待执行 → 检查登录 → 搜索帖子 → 读取详情 → 读取评论 → 输出报告 → 成功／部分成功／失败

- 任一步骤失败时保留此前取得的数据，并记录失败阶段。
- 重复运行时使用平台帖子ID和评论ID识别同一业务对象。

### 帖子与评论

首次发现 → 提取原始字段 → 标准化 → 写入本地验证结果

- 本阶段不删除平台已消失的内容。
- 评论必须保留所属帖子ID；二级回复还要保留父评论ID。

## 五个必问

### Q1 空状态

- 未登录时输出`auth_required`，提示用户在打开的浏览器中登录。
- 搜索无结果时输出成功状态和空列表，不伪造样本。
- 相关帖子不足时在报告中记录实际数量。

### Q2 失败

- 页面加载超时：记录`page_timeout`和当前阶段，有限重试后退出。
- 登录失效：记录`auth_required`，不继续访问详情页。
- 页面结构变化：记录`field_missing`及缺失字段，不用猜测值补齐。
- 访问限制或验证码：停止当前任务，记录页面提示，不自动绕过。

### Q3 被引用

- 输出中的帖子和评论均保留原始链接或所属帖子链接。
- 原始快照与标准化结果分开，后续解析规则变化时可以复核。

### Q4 并发

- 验证探针同一时间只允许一个进程使用本地浏览器目录。
- 已有进程运行时，新进程直接失败并给出占用提示。

### Q5 后悔与撤销

- 本阶段只读取网站内容，不点赞、不收藏、不关注、不评论、不发布。
- 本地验证输出可以直接删除；登录目录只能由用户明确决定是否清除。

## 输入输出链

### 输入

- 关键词：命令行参数，默认值为`Leader`。
- 本地浏览器目录：用于保存用户主动完成的登录状态。
- 采集上限：帖子和评论数量必须设置小范围上限。

### 输出

- `artifacts/xhs-probe/<运行标识>/report.json`：任务状态、字段覆盖和错误摘要。
- `artifacts/xhs-probe/<运行标识>/posts.json`：标准化帖子数据。
- `artifacts/xhs-probe/<运行标识>/comments.json`：标准化评论和回复关系。
- `artifacts/xhs-probe/<运行标识>/raw/`：不含Cookie和Token的页面原始字段快照。

`artifacts/`和本地浏览器目录不得进入Git。

## 子功能优先级

### 必须实现

1. 使用持久化浏览器目录检查登录状态。
2. 按关键词读取搜索结果，并保留帖子平台ID和完整原始链接。
3. 读取帖子正文、作者、时间、地区、话题、图片和互动数据。
4. 读取评论ID、正文、作者、时间、地区、点赞数和父子关系。
5. 输出脱敏JSON和字段能力报告。
6. 对超时、登录失效、验证码、字段缺失和结构变化给出明确错误。
7. 限制访问数量和频率，禁止批量高频访问。

### 应该实现

1. 根据`统帅、海尔`和品类词标记品牌相关性，保留未过滤的原始搜索结果数量。
2. 对同一帖子和评论重复出现进行去重。
3. 对发布时间来源标记可信等级，页面展示与结构化字段冲突时保留两者。

### 可以延后

1. MySQL写入。
2. 每小时调度。
3. 图片文字识别。
4. 全量评论翻页和长期稳定性测试。

## 验收标准

### AC-1：登录状态检查

- 前置：本地浏览器目录未登录或登录已失效。
- 操作：运行采集探针。
- 期望：浏览器以可见方式打开；程序输出`auth_required`；用户登录后可以继续执行；日志和输出中不包含Cookie、Token、手机号或验证码。
- 关联子功能：必须实现1、6。

### AC-2：搜索Leader帖子

- 前置：登录状态有效，关键词为`Leader`。
- 操作：执行一次搜索，读取不超过20条结果。
- 期望：结果包含平台帖子ID、标题、作者、展示时间、互动摘要和原始链接；同时记录原始结果数及品牌相关结果数。
- 关联子功能：必须实现2、7，应该实现1。

### AC-3：帖子详情字段

- 前置：搜索结果中存在与Leader统帅家电相关的帖子。
- 操作：读取不超过3篇帖子详情。
- 期望：每篇输出`noteId`、`title`、`description`、`author`、`ipLocation`、`time`、`lastUpdateTime`、`tags`、`imageUrls`、`likedCount`、`collectedCount`、`commentCount`、`shareCount`和`sourceUrl`；缺失字段使用`null`并写入报告，不伪造值。
- 关联子功能：必须实现3、5、6。

### AC-4：评论和回复关系

- 前置：目标帖子存在评论。
- 操作：读取首批评论及已展开的回复。
- 期望：每条评论输出`commentId`、`noteId`、`parentCommentId`、`content`、`author`、`publishedText`、`ipLocation`和`likedCount`；一级评论的`parentCommentId`为`null`，二级回复指向所属一级评论ID。
- 关联子功能：必须实现4、5。

### AC-5：幂等去重

- 前置：同一帖子或评论在一次运行中重复出现。
- 操作：完成标准化输出。
- 期望：`posts.json`中相同`noteId`只保留一条；`comments.json`中相同`commentId`只保留一条；报告记录去重前后数量。
- 关联子功能：应该实现2。

### AC-6：时间字段冲突

- 前置：页面展示时间与JSON-LD或原始状态时间不一致。
- 操作：提取并标准化时间。
- 期望：保留原始时间值及其来源；报告标记`time_conflict`；不得用采集时间冒充发布时间。
- 关联子功能：应该实现3。

### AC-7：失败时保留证据

- 前置：详情读取或评论读取过程中发生超时、验证码、访问限制或字段缺失。
- 操作：等待任务结束。
- 期望：程序返回非零退出码或`partial_success`；已经取得的帖子和评论仍写入结果；报告包含失败阶段、错误类型和脱敏摘要。
- 关联子功能：必须实现5、6。

### AC-8：只读与低频限制

- 前置：运行任意一次验证任务。
- 操作：检查实现和运行记录。
- 期望：不存在点赞、收藏、关注、评论和发布操作；默认最多读取20条搜索结果、3篇详情，每次详情访问之间至少等待2秒。
- 关联子功能：必须实现7。
