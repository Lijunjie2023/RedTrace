# ReadTrace舆情监控台UI方案

文档日期：2026-08-06
适用范围：桌面优先、响应式Web产品
目标路由：概览、原因洞察、内容库、品牌监控、数据状态、登录、内容详情与人工修正
方案线路：B线，采用`frontend-design`

## 1. 结论

第一版采用编辑部调查台的视觉方向。界面以近纸色背景、石墨色正文和朱红风险色为主，避免常见的蓝紫渐变数据大屏。核心页面都遵循同一条阅读路径：先看到风险变化，再看到原因，最后回到原帖或原评论。

模拟数据不得只在页脚说明。只要当前数据不是正式采集结果，系统必须同时出现以下三类标识：

1. 全局顶部固定横幅显示「当前为模拟模式，页面数据仅用于界面验收，不代表真实舆情」。
2. 所有统计卡、图表、排行、内容列表和详情页显示「模拟数据」印章。
3. 导出按钮显示「导出模拟数据」，文件名和工作表名称也包含「模拟」字样。

没有正式数据时，禁止用模拟数据覆盖真实数据空状态。正式模式、模拟模式和混合验证环境必须由后端返回明确的数据模式，前端不能自行猜测。

## 2. 项目现状与设计语言映射

| 项目 | 当前事实 | 本方案处理 |

## 3. B线设计判断

### 3.1 Design Thinking四问

| 问题 | 答案 |
|---|---|
| Purpose | 帮助领导层、策划岗和运营岗发现负面变化，理解核心原因，并快速回看原帖或原评论。 |
| Tone | 编辑部调查台，接近研究员使用的证据档案和风险简报，不采用炫技数据大屏。 |
| Constraints | 桌面优先并适配375、768、1024、1440四档宽度；需要满足键盘操作、中文断行、图表可访问性和高密度数据浏览。 |
| Differentiation | 每个结论旁边都有证据数量和「查看证据」入口，进入详情后沿一条朱红证据线看到原文、上下文、模型判断和人工修正记录。 |

### 3.2 五项审美决策

| 项目 | 决策 | 依据 |
|---|---|---|
| Typography | 标题和重点数字使用阿里妈妈数黑体，正文使用思源黑体，表格数字使用JetBrains Mono。 | 中文标题保留数据编辑感，正文仍然适合长时间阅读。 |
| Color & Theme | 近纸色为主背景，石墨色承载正文，朱红色只表达风险和主操作，青绿色表达正向与成功。 | 风险需要清楚，但不能把整个产品做成红色警报屏。 |
| Motion | 仅在全局筛选刷新、详情抽屉进入、保存人工修正和任务状态变化时使用动画。 | 用户主要在读数据，动画需要服务状态理解。 |
| Spatial Composition | 使用不对称的主结论区与证据侧栏，列表页采用筛选、列表、预览三段工作区。 | 让结论和证据同时出现，避免标准四卡加图表模板。 |
| Background Details | 使用低透明档案线、页码式序号和朱红证据线，装饰不覆盖正文。 | 这些细节与证据追溯场景直接相关。 |

## 4. 信息架构与导航

### 4.1 主导航

主导航固定为五项，顺序如下：

1. 概览：快速判断负面变化、风险内容和数据是否正常。
2. 原因洞察：分析负面原因、正向卖点、关键词和对应证据。
3. 内容库：检索帖子和评论，组合筛选并导出。
4. 品牌监控：维护品牌、相关词和采集开关。
5. 数据状态：查看采集任务、数据延迟、异常下降和重试记录。

辅助路由不进入主导航：

- 登录：未认证用户的独立页面。
- 内容详情与人工修正：从概览、原因洞察或内容库进入，保留来源页筛选状态。

分类配置第一版并入品牌监控页的「分类词表」二级标签，不增加第六个主导航。这样保留PRD功能，同时满足五个主导航的约束。

### 4.2 全局应用壳

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 产品名  当前品牌范围  数据更新时间              搜索  管理员  退出 │
├─────────────────────────────────────────────────────────────────────┤
│ 模拟模式固定横幅：当前数据仅用于界面验收，不代表真实舆情          │
├──────────────┬──────────────────────────────────────────────────────┤
│ 五项主导航   │ 页面标题  页面说明                    页面主操作     │
│              ├──────────────────────────────────────────────────────┤
│ 数据健康摘要 │ 全局筛选条                                           │
│              ├──────────────────────────────────────────────────────┤
│              │ 页面内容区                                           │
└──────────────┴──────────────────────────────────────────────────────┘
```

桌面端左侧导航宽232px，顶部工具栏高64px。模拟模式横幅高36px并固定在顶部工具栏下方。页面主内容在1440px以上保持最大可读宽度1680px，左右留白至少32px；1024至1439px将导航收为72px图标栏，文字通过悬停和键盘聚焦提示；768至1023px改为顶部紧凑导航；767px以下使用五项底部导航。

底部导航恰好五项，符合移动端导航数量限制。所有导航项显示图标和文字，当前位置使用左侧实线或底部实线加粗，不能只通过颜色区分。

## 5. 全局信息层级

### 第一层级

- 负面数量、负面占比和相较上一周期的变化。
- 高风险内容数量与新增数量。
- 增长最快的负面原因。
- 数据是否按计划更新。

使用`type.metric`或`type.page-title`、`color.ink.primary`和有限的`color.risk`强调。每个结论同时显示统计范围和证据入口。

### 第二层级

- 情感趋势、品类排行、问题类型排行。
- 代表性原帖和原评论。
- 当前筛选条件、更新时间和数据完整性。
- 页面主操作，例如查看证据、导出、触发更新和保存修正。

使用`type.section-title`、`type.body`和主文字色。主操作在同一区域只出现一次。

### 第三层级

- 点赞数、收藏数、评论数、作者公开信息和采集时间。
- 模型版本、分析时间、任务编号和来源词。
- 次要说明、帮助文本和历史操作记录。

使用`type.label`、`color.ink.secondary`或`color.ink.tertiary`。重要证据元数据仍需保持可读对比度。

## 6. 全局数据模式与状态规范

### 6.1 模拟模式

模拟模式使用三重提示：

- 顶部固定横幅：左侧为烧杯图标，正文为「当前为模拟模式，页面数据仅用于界面验收，不代表真实舆情」，右侧提供「查看说明」。横幅不可关闭。
- 数据区印章：每个图表、排行和内容区右上角显示`模拟数据`文字印章。印章使用`color.warning.soft`底色和`color.warning`文字，不覆盖数据。
- 导出提示：按钮文案改为「导出模拟数据」。点击后弹窗再次说明用途，导出文件名格式为`ReadTrace_模拟数据_页面名_日期.xlsx`。

浏览器标题追加`[模拟]`。分享链接或复制截图的页头区域必须保留模拟模式横幅，避免截掉提示后形成误解。

### 6.2 数据状态不得混用

| 状态 | 页面呈现 | 禁止做法 |
|---|---|---|
| 尚未采集 | 空白档案图标，说明预计首次采集时间，提供前往品牌监控入口 | 显示为0条负面 |
| 正常 | 显示最后成功时间和绿色正常图标 | 只写更新时间，不说明是否成功 |
| 延迟 | 顶部数据健康条使用提醒图标，统计仍显示上次成功数据并标注截止时间 | 把旧数据当作当前数据 |
| 采集失败 | 红色错误图标加错误摘要，统计保留上次成功值，显示「数据截至…」 | 将统计清零 |
| 部分成功 | 显示成功与失败数量、缺失范围和重试入口 | 只显示成功状态 |
| 筛选无结果 | 保留筛选条件，说明没有符合条件的内容，提供清除筛选 | 显示成系统尚未采集 |
| 加载中 | 保留页面骨架结构，图表使用低对比占位，不闪烁 | 用旋转图标遮住整页 |

## 7. 路由一：概览

### 7.1 页面目的

领导层可以在一分钟内回答四个问题：负面是否增加、主要增加在哪里、有哪些高风险证据、数据是否完整。

### 7.2 桌面布局

```text
┌───────────────────────────────┬──────────────────────┐
│ 负面风险摘要，8列             │ 高风险证据队列，4列   │
│ 负面占比、增量、最快原因       │ 3至5条原文摘要         │
├───────────────────────────────┴──────────────────────┤
│ 情感趋势，12列，支持点选区间并进入内容库              │
├───────────────────────────────┬──────────────────────┤
│ 原因增长榜，7列               │ 品类与问题排行，5列    │
├───────────────────────────────┴──────────────────────┤
│ 品牌对比表与数据完整性说明                              │
└──────────────────────────────────────────────────────┘
```

风险摘要不是四个等宽卡片。左侧用一个连续面板显示负面数量、负面占比和周期变化，右侧沿朱红证据线显示增长最快的原因及证据数量。高风险队列与摘要同屏，领导看到数字后不需要滚动才能找到原文。

### 7.3 关键组件

- 风险摘要：主数字为负面内容数，次级显示负面占比和环比。变化值带方向箭头和文字「上升」或「下降」。点击进入内容库并带入情感、时间和品牌筛选。
- 高风险证据队列：每条显示内容类型、原文两行、风险原因、点赞数、发布时间和「查看证据」。原文超过两行截断，完整内容在详情页展示。
- 情感趋势：正向、中性、负向分别使用颜色、线型和图例符号区分。悬停提示显示日期、数量、占比和数据截止时间。键盘可逐点导航。
- 原因增长榜：使用带页码序号的横向条，不使用词云。每项显示内容数、变化幅度和证据数。
- 数据健康条：始终显示最后成功采集时间、覆盖品牌数、当前是否延迟。异常时置于页面标题下方，不得隐藏在页脚。

## 8. 路由二：原因洞察

### 8.1 页面目的

策划岗从负面原因或正向卖点进入主题，再查看关键词和代表性原文。

### 8.2 桌面布局

```text
┌──────────────┬────────────────────────────┬──────────────────┐
│ 筛选栏，260px │ 主题排行与趋势，弹性宽度    │ 证据侧栏，360px   │
│ 品牌          │ 正向与负向分段切换          │ 代表性原帖与评论   │
│ 品类与型号    │ 原因说明、数量、增幅         │ 原始链接与互动数   │
│ 问题类型      │ 关键词表                     │                  │
└──────────────┴────────────────────────────┴──────────────────┘
```

默认进入负向视图。正向与负向是分段控件，不将二者画在同一排名中。选择原因主题后，右侧证据栏立即更新并保留主题说明。证据栏不是临时tooltip，用户可以继续打开完整详情。

### 8.3 主题与关键词规则

- 原因主题行显示名称、说明、内容数、涉及用户数、总点赞数、变化幅度和证据数。
- 关键词表显示出现次数、帖子数、评论数、用户数、总点赞数和变化幅度，数字右对齐。
- 点击主题或关键词后，URL写入对应筛选参数，刷新和返回后仍然保留状态。
- 原因主题没有证据时显示数据质量错误，不允许进入正式排行。
- 低可信度主题显示提醒图标和「待复核」，不能只把文字变黄。

## 9. 路由三：内容库

### 9.1 页面目的

运营岗高效查找帖子和评论，核对上下文、分类结果和原始链接，并导出当前筛选结果。

### 9.2 桌面布局

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 筛选栏，280px │ 内容列表，最小560px           │ 预览栏，380px     │
│ 可折叠分组    │ 帖子/评论分段切换             │ 原文与有效分析     │
│ 当前条件数量  │ 排序、总数、批量导出           │ 查看详情           │
└──────────────┴──────────────────────────────┴──────────────────┘
```

筛选项包括时间、品牌、品类、系列、型号、情感、内容性质、问题类型、风险程度、关键词、原因主题和内容类型。已生效条件同时显示在列表上方的可移除条件条中。筛选栏底部固定「清除全部」和结果数量。

### 9.3 内容行

每行显示：

- 帖子或评论图标及文字类型。
- 原文摘要，帖子最多三行，评论最多四行。
- 品牌、品类、问题类型、原因主题和风险状态。
- 点赞、收藏或评论互动数字。
- 发布时间、最后采集时间和原始链接入口。
- 分析可信度与是否经过人工修正。

原始链接使用外链图标和「打开原帖」文字，需在新标签页打开并添加安全属性。评论行提供「查看所属帖子」。点击列表空白区域更新右侧预览，点击明确的「查看详情」进入辅助路由。

### 9.4 导出

导出按钮旁显示当前结果数量。超过同步导出阈值时，弹窗说明转为后台任务，并在完成后提供下载。导出失败不提供文件，只显示失败原因和重试操作。模拟模式下按钮、弹窗、文件名和工作表名均保留模拟标识。

## 10. 路由四：品牌监控

### 10.1 页面结构

页面顶部使用二级标签：

- 监控品牌。
- 分类词表。

监控品牌使用台账列表，不使用大面积品牌卡片。每行显示品牌名称、启用状态、别名和产品词数量、最后成功采集时间、最近任务状态、连续失败次数和操作。

### 10.2 新增与编辑

新增和编辑使用右侧抽屉，宽560px。表单字段分为基本信息、品牌相关词、产品与型号词、排除词、监控周期五组。多值字段使用可编辑标签，输入后按回车确认。每个字段都有可见label和帮助文本，不使用placeholder替代label。

发现重复品牌、别名冲突或排除词冲突时，在对应字段下方显示图标、说明和冲突对象。停用品牌前使用确认弹窗，明确说明「停止后不再创建新的定时采集任务，历史数据仍然保留」。

手动更新按钮点击后进入加载状态，并显示任务已创建及任务编号。活跃任务期间按钮禁用并显示「更新进行中」。失败后提供「查看数据状态」，不在品牌行里塞入完整错误堆栈。

### 10.3 分类词表

分类词表按产品品类、问题类型、原因主题三个标签展示。每项可以编辑显示名称、说明、排序和启用状态。被历史数据引用的项目不显示删除操作，只允许停用，并说明引用数量。

## 11. 路由五：数据状态

### 11.1 页面目的

管理员确认每小时任务是否成功，数据是否延迟，以及失败后能否安全重试。

### 11.2 页面布局

顶部不放普通数据卡，改为24小时采集心跳带。横轴为小时，纵向按品牌排列，每个单元格同时使用图标、纹理和文字缩写区分成功、部分成功、失败、运行中和未执行。点击单元格筛选下方任务台账。

下方任务台账显示任务编号、品牌、触发方式、开始时间、结束时间、持续时间、状态、帖子数、评论数和错误摘要。数字使用`font.numeric`并右对齐。错误摘要最多两行，完整信息在详情抽屉展示，但不得显示凭证或原始请求。

连续失败和数据量异常下降使用页面级告警条，告警中写明受影响品牌、最后成功时间和可执行操作。点击重试时需要确认目标任务；重试创建新任务并保留原任务，不把原任务状态改成成功。

### 12.1 布局

登录页保持克制，不展示任何舆情统计或虚构图表。账号和密码都有可见label。密码提供显示与隐藏按钮，该按钮可被屏幕阅读器识别。提交期间按钮显示「正在登录」并禁用重复提交。

登录失败统一显示「账号或密码不正确，或当前账号暂时无法登录」，不说明账号是否存在。错误提示位于表单顶部，同时在对应表单组使用错误图标和边界变化。未认证访问业务页后跳转登录，登录成功应返回原目标页；直接登录则进入概览。

## 13. 辅助路由：内容详情与人工修正

### 13.1 桌面布局

```text
┌─────────────────────────────┬────────────────────┬──────────────────┐
│ 原文与媒体，6列              │ 上下文与证据，3列    │ 人工修正，3列     │

└─────────────────────────────┴────────────────────┴──────────────────┘
```

页面顶部保留返回来源页操作，并显示来源页筛选摘要。浏览器后退必须回到原列表位置和滚动位置。

### 13.2 证据区

- 原文完整展示，正文默认不截断。
- 评论详情先显示所属帖子摘要，再显示父评论、当前评论和必要回复上下文。
- 原帖链接、发布时间、采集时间、最后更新时间和互动数据靠近原文展示。
- 图片与OCR结果建立对应关系。图片加载失败时保留替代文字和OCR文本。
- 朱红证据线只位于三栏之间的留白区，不与文字重叠。

### 13.3 人工修正区

右栏顶部并列显示「模型原始结果」和「当前有效结果」，被人工修改的字段显示「人工修正」图标、修正时间和差异。可修正字段包括情感倾向、内容性质、问题类型、品类、系列、型号、用户阶段、风险程度和原因主题。

问题类型使用多选控件。保存前显示变更摘要。保存成功后用页内状态条提示，并更新有效结果；保存失败时保留用户输入，显示失败原因和重试操作。离开存在未保存修改的页面前需要确认。

模型原始结果永远只读。恢复模型结果需要二次确认，并生成新的人工操作记录，不能删除历史修正记录。

所有可交互组件都遵守以下状态：

| 状态 | 规格 |
|---|---|
| 默认 | 使用语义背景和正文色，边界清楚，操作文字不低于`type.body`。 |
| Hover | 在`motion.fast`内改变背景色或边界，不移动布局；同时保留文字说明。 |
| Active | 使用`color.ink.primary`强调边界或下划线，持续时间为`motion.fast`。 |

| Loading | 保留原尺寸，显示进度图标和进行中文字，避免页面跳动。 |
| Error | 使用错误图标、`color.risk`边界和就近说明，不只显示红字。 |

### 14.3 重点组件补充

#### `GlobalFilterBar`

- 默认：横向显示时间、品牌和页面主要筛选；高级筛选进入抽屉。
- Hover：字段背景使用`color.surface.raised`。
- Active：展开面板时字段边界使用`color.ink.primary`。
- Disabled：数据源不可用时显示原因，不允许空白禁用。
- 超长内容：品牌多选超过两项后显示前两项加「另有N项」。
- 响应式：768px以下收为「筛选」按钮，按钮显示有效条件数量。

#### `EvidenceItem`

- 默认：显示内容类型、原文摘要、互动数、发布时间和原始链接。
- Hover：左侧证据线加粗，背景轻微提升。
- Active：选中后保留`color.risk.soft`浅底和明确「已选择」文字。
- Disabled：原始链接失效时显示「原链接暂不可用」，仍可查看已保存证据。
- 超长内容：列表中按行数截断，详情中完整显示；任何截断都提供可访问的展开方式。

#### `DataTable`

- 默认：表头固定，数字右对齐，文本左对齐，行高48px。
- Hover：整行使用`color.surface.raised`，不改变文字颜色。
- Active：键盘或鼠标选中行后显示左侧2px强调线和选中说明。
- Disabled：仅用于不可操作行，数据本身仍保持正常对比度。
- 超长内容：名称一行省略，错误摘要两行省略，悬停不能作为唯一查看完整内容的方式。
- 小屏：转换为字段明确的纵向记录，不强制横向滚动。

#### `SideDrawer`

- 入场：从右侧进入，使用`motion.enter`；遮罩同步渐入。
- 出场：使用`motion.fast`，比入场更快。
- 焦点：打开后焦点移至标题，关闭后返回触发按钮，焦点锁定在抽屉内。
- 尺寸：品牌表单560px，证据预览420px，任务详情520px；小于768px时占满宽度。
- 关闭：支持明确关闭按钮和Esc；存在未保存内容时需确认。

## 15. 交互与动效

- 全局筛选刷新：内容区在`motion.base`内降低透明度并显示局部骨架，旧数据保留到新请求返回。请求失败时恢复旧数据并显示错误条。
- 页面首次进入：只让页面标题、首个风险摘要和证据队列依次进入，总时长不超过420ms。列表行不逐条飞入。
- 图表筛选：点击数据点后使用`motion.fast`显示选中标记，再进入带筛选条件的内容库。
- 抽屉与弹窗：入场使用`motion.enter`，出场使用`motion.fast`。遮罩不得抢先消失。
- 人工修正保存：保存按钮显示加载状态；成功后变为带图标的「已保存」，约1.5秒后恢复。
- 任务状态：运行中到成功或失败的变化使用`motion.base`淡入新状态，不使用闪烁。
- 用户启用`prefers-reduced-motion`后，取消位移、依次入场和数字滚动，只保留不超过150ms的透明度变化。

## 17. 可访问性与工程底线

- 每个输入框都有持久可见label，必填项显示文字标识。失焦后校验，禁止逐字符报错。
- 所有按钮、链接、标签页和图表数据点都可通过键盘访问，焦点顺序符合视觉顺序。
- 图表提供图例、tooltip和可下载的数据表。数据系列同时使用颜色、线型和符号区分。
- 状态标签同时包含图标和文字。负向、失败和高风险不能只使用红色。
- 装饰性档案线和证据线使用独立图层，并避开标题、正文、tooltip和可点击区域。
- 页面区分加载中、尚未采集、采集失败、筛选无结果、部分成功和正常六类状态。
- 弹窗与抽屉满足焦点锁定、焦点返回、Esc关闭和屏幕阅读器标题关联。
- 原文、作者公开信息和OCR文本按不可信内容处理，显示层不得执行其中的HTML或脚本。
- 原始链接在新标签页打开，并提供可见域名或平台名称，避免不清楚的跳转。

## 18. 文案规范

- 使用业务语言，例如「最后成功采集时间」，避免显示游标、租约、CAS等实现术语。
- 风险结论必须带统计范围，例如「过去7天，Leader相关负面内容28条」。
- 无证据时不能输出确定性原因，可以显示「暂未形成可验证的原因主题」。
- 数据延迟时写明截止时间，例如「采集失败，当前统计沿用截至8月6日14:00的成功数据」。
- 低可信度使用「待复核」，并说明哪些字段需要人工确认。
- 按钮使用明确动作：查看证据、打开原帖、保存修正、重新执行、导出模拟数据。

## 19. 自检结果

### 19.1 B线反AI套路自检

- 字体未使用Inter、Roboto、Arial或系统默认字体作为主字体。
- 配色没有使用紫色渐变白底，也没有平均分配多个强调色。
- 概览没有采用四个等宽指标卡加三张图表的标准模板，首屏让风险摘要与高风险证据同时出现。
- 页面特征来自舆情证据回溯场景，包括证据线、档案序号、原文入口和数据截止时间，不靠通用玻璃拟态装饰。

### 19.2 项目一致性自检

- 去掉颜色后，标题、风险数字、原因说明、证据入口和辅助元数据仍有明确字号与位置层级。
- 缩小到60％时，左侧导航、主结论和右侧证据的视觉重心保持平衡。
- 同类按钮、状态标签、筛选条件和证据条目使用同一套公共组件。
- 没有功能相同但外观不同的重复组件。
- 高密度列表通过分组、固定表头和预览栏组织，未用紧密卡片堆满页面。
- 除中性色外只使用风险朱红、正向青绿和提醒赭色三种色相。

### 19.3 工程底线自检

- 已规定文字对比度、可见焦点环、非颜色状态表达和键盘操作。
- 已规定移动端44×44px点击目标与8px间距。
- 已规定表单label、错误位置、校验时机和必填标识。
- 已规定四档断点、移动端最小字号和禁止横向滚动。
- 已规定中文断行、装饰图形避让和字体加载纪律。
- 已规定150至300ms状态动效、减少动态效果偏好和入场慢于出场。
- 已规定图例、tooltip、辅助数据表和图表空错加载状态。
- 已规定公共交互组件的默认、Hover、Active、Focus、Disabled、Loading和Error状态。

## 20. 待决策项

1. 是否在前端开发启动时建立独立token文件。项目目前没有设计系统，本方案建议建立最小语义token，避免七个路由各自硬编码。

3. 模拟模式是否允许普通管理员切换。推荐只由环境配置或后端权限控制，避免用户在页面误切到模拟数据。
4. 内容详情中的小红书图片是否允许缓存展示，需要结合平台规则、个人信息保护和内部使用边界确认。
5. 大数据量导出的同步阈值需要后端根据真实性能确定，界面预留后台任务状态。

## 21. 给code-writer的交付说明

本方案扫描了项目`AGENTS.md`、完整PRD、当前文件结构和`package.json`相关现状。仓库没有前端、UI组件库、设计token或可复用页面，因此所有界面组件均为新增建议。

实施时优先建立色彩、字体、间距、圆角、阴影和动效的最小语义token。组件不得直接散落裸颜色值。B线采用`frontend-design`，落地时需要保持以下五项决定：阿里妈妈数黑体配思源黑体；近纸色、石墨色和朱红风险色；动画只服务筛选、浮层、保存和状态变化；结论区与证据侧栏采用不对称布局；背景只加入低透明档案线和证据线。

模拟模式属于P0安全约束。任何接口返回模拟数据时，必须同步触发全局横幅、数据区印章、按钮文案、导出文件名和浏览器标题变化。正式数据为空时不得自动回退到模拟数据。

实施后需要分别验证1440、1024、768和375px宽度，完成键盘导航、屏幕阅读器标签、减少动态效果、图表辅助数据表、所有空错加载状态，以及从图表和排行进入带筛选条件内容库的完整返回路径。
