# DeepSeek自动分析与手动触发验收标准

## 范围

系统每30分钟自动扫描尚无当前有效结果的帖子和评论，也允许管理员在数据管理页面手动触发同一流程。每轮最多处理10篇帖子和10条评论，不在页面请求中同步等待模型结果。

## B1 实体与生命周期

### 分析运行

生命周期：待触发 → 申请全局锁 → 运行中 → 成功、部分成功、失败或因已有任务而跳过。

- 自动定时和管理员手动触发共用同一把数据库全局锁。
- 取得锁后先分析帖子，再分析评论；不可恢复错误停止本轮，已有成功结果保留。
- 进程退出或连接断开后数据库连接级锁自动释放，单条内容的既有租约负责恢复未完成尝试。
- 分析运行不删除帖子、评论、历史模型结果或人工修正。

### 定时器

生命周期：安装 → 启用 → 每30分钟触发 → 可停用或重新启用。

- API服务重启不影响定时器。
- 服务器停机错过周期后，恢复时允许补触发一次。

## B2 五个必问

- 空状态：没有待分析内容时运行成功结束，处理数和Token用量均为0。
- 失败：DeepSeek不可用时记录脱敏错误；数据库不可用时不调用模型；页面手动触发失败时显示服务错误。
- 被引用：页面继续读取最近成功结果；失败运行不能覆盖成功结果或人工修正。
- 并发：自动和手动同时触发时只有一个取得全局锁，另一个返回正在分析，不重复消耗Token。
- 撤销：分析结果不物理删除；人工修正仍独立保存。管理员可以停用定时器，但已完成结果保持不变。

## B3 输入输出

输入：MySQL待分析帖子、评论、启用分类词表、DeepSeek配置、自动定时事件或管理员手动请求。

输出：`analysis_records`及分类关联、批次汇总、页面运行状态、systemd日志。日志不得包含密钥、Authorization、完整帖子正文、完整评论正文或模型原始响应。

## B4 子功能

### 必须实现

1. 帖子和评论统一分析入口，每类最多10条。
2. MySQL全局互斥锁，自动与手动触发共用。
3. 管理员手动触发API，立即返回受理或运行中状态。
4. 数据管理页面手动按钮和运行反馈。
5. `systemd service + timer`，每30分钟触发并支持开机补触发。
6. 部署、启用、验证和日志查看文档。

### 应该实现

1. 自动刷新数据管理页面的最近分析状态。
2. 自动和手动来源写入安全汇总日志。

## 验收标准

### AC-1：统一分析入口
- 前置：数据库同时存在待分析帖子和评论。
- 操作：执行统一分析入口。
- 期望：先运行帖子批次，再运行评论批次；每类上限为10；输出只包含数量、Token用量、停止原因和安全错误代码。

### AC-2：没有待分析内容
- 前置：所有内容已存在当前成功结果。
- 操作：执行统一分析入口。
- 期望：帖子和评论处理数均为0，DeepSeek调用次数和Token用量均为0，运行状态为成功。

### AC-3：全局并发锁
- 前置：一个分析运行已经取得全局锁。
- 操作：同时触发自动运行和管理员手动运行。
- 期望：只有一个运行模型批次；另一个返回`already_running`，不调用DeepSeek。

### AC-4：手动触发API
- 前置：管理员已经登录。
- 操作：调用手动分析接口。
- 期望：空闲时返回HTTP 202和`started=true`；运行中返回HTTP 202和`started=false`、`reason=already_running`；未登录请求返回401。

### AC-5：手动触发界面
- 前置：打开数据管理页面。
- 操作：点击`立即分析`。
- 期望：请求期间按钮禁用并显示`正在启动`；受理后显示`分析任务已经启动`；已有任务时显示`当前已有分析任务正在运行`；失败时显示可重试错误。

### AC-6：定时分析
- 前置：安装并启用systemd单元。
- 操作：检查timer配置和下一次触发时间。
- 期望：`OnBootSec=5min`、`OnUnitActiveSec=30min`、`Persistent=true`；service使用`readtrace`账号和受控环境文件执行统一分析入口。

### AC-7：失败隔离与恢复
- 前置：帖子批次部分成功后评论批次遇到不可恢复错误，或进程异常退出。
- 操作：等待本轮结束并再次触发。
- 期望：已有成功结果保留；失败信息不含正文或密钥；数据库连接释放后全局锁自动释放；下次运行可以重新领取未成功内容。

### AC-8：部署验证
- 前置：代码已经提交并推送到线上服务器。
- 操作：安装单元、重载systemd、启用timer并手动启动一次service。
- 期望：timer处于active；service退出状态成功或明确报告安全错误码；API和Nginx原有服务保持运行；线上接口返回结构化响应。
