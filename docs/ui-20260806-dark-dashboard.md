# ReadTrace暗色舆情看板改版方案

文档日期：2026-08-06
适用范围：概览、原因洞察、内容库、品牌监控、数据状态、登录、内容详情与人工修正
实施优先级：先统一应用壳与概览页，再让其余页面继承同一设计系统
设计线路：B线，采用`frontend-design`

## 1. 结论

ReadTrace改为生产级暗色分析后台。视觉参考用户提供的暗色舆情大屏，但不照搬其中无法由现有接口支持的指标。新版使用炭黑工作区、分层灰面板和高辨识度风险红，保持较高信息密度，同时把每个分析结论继续连接到原帖或原评论。

第一阶段只展示现有合同能够提供的数据：帖子数、评论数、负面数量、负面占比、情感趋势、品牌排行、品类排行、问题类型排行、上升主题、高风险内容、采集健康状态和最后成功时间。参考图中的“上周同期”“影响帖数”“评论数”“数据覆盖率”“重复率”“风险数据过滤”等字段不进入首版，除非后端先补充合同与真实查询。

当前正式模式下`/overview`返回`DATA_NOT_READY`时，界面不能伪造大屏数据。新版需要把“统计分析尚未准备完成”与“数据库或网络请求失败”区分开，同时提供内容库和数据状态入口，避免用户只看到一块错误横幅和整页空白。

## 2. 项目现状与设计语言映射

### 2.1 扫描范围

- 应用壳：`apps/web/src/layout/app-shell.tsx`
- 公共组件：`apps/web/src/components/common.tsx`、`apps/web/src/components/page.tsx`
- 页面：`apps/web/src/pages/overview.tsx`、`insights.tsx`、`content.tsx`、`content-detail.tsx`、`brands.tsx`、`data-status.tsx`、`login.tsx`
- 样式：`apps/web/src/styles.css`
- 数据合同：`packages/contracts/src/index.ts`
- 既有方案与原型：`docs/ui-20260806-monitoring-console.md`、`docs/prototypes/readtrace-dashboard-prototype.html`
- 用户参考图：暗色RedTrace舆情大屏与当前线上错误页截图

### 2.2 当前事实

| 项目 | 当前实现 | 本次改版策略 |
|---|---|---|
| 框架 | React 19、React Router 7、Vite 7 | 保持现有技术栈，不引入页面框架 |
| UI与图表库 | 没有外部UI库和图表库 | 首期复用现有组件，图表继续使用轻量DOM、CSS或内联SVG |
| 样式系统 | 单一`styles.css`，使用CSS变量和语义类名 | 保留变量名，重映射为暗色值；新增变量延续`--color-*`、`--type-*`命名 |
| 字体 | 阿里妈妈数黑体、Noto Sans SC、JetBrains Mono及后备字体 | 保留三类字体角色，不改字体加载策略 |
| 页面结构 | 固定顶栏、固定侧栏、五项主导航、页面标题、筛选条、面板 | 保留五项信息架构，重做壳层比例和视觉层级 |
| 响应式 | 1439、1023、767三个断点 | 保留断点，调整暗色导航与密集面板的折叠规则 |
| 数据模式 | `MOCK`或`LIVE`，模拟数据有横幅和印章 | 保留并强化，正式数据不显示模拟印章 |
| 错误状态 | 通用错误横幅，初次失败时页面主体为空 | 按错误类型区分，并提供可继续使用的业务入口 |

| 类别 | 规则 |

| 正文 | 继续使用`--font-body`和`--type-body`，中文正文行高不低于1.5 |
| 数字 | 统计值、时间、百分比和任务编号使用`--font-numeric`，启用等宽数字 |
| 间距 | 保留`--space-1`至`--space-8`的4px基准，主要面板内边距使用`--space-4`或`--space-5` |

| 边框 | 面板使用一像素暗灰边界；当前选中项可加风险色左边线或底边线 |
| 动效 | 保留`--motion-fast`、`--motion-base`、`--motion-enter`，支持减少动态效果偏好 |

## 3. 设计判断

### 3.1 Design Thinking四问

| 问题 | 答案 |
|---|---|
| Purpose | 让领导层在一分钟内判断负面变化，让策划岗理解原因，让运营岗快速回到可核验的原帖、评论和采集记录。 |
| Tone | 克制的暗色情报分析台，接近专业监测终端，但不做军用终端式噪声和无意义炫光。 |
| Constraints | React现有代码、无UI库、真实API字段有限、桌面优先、中文密集阅读、键盘可操作、移动端仍需完成核心任务。 |
| Differentiation | 风险曲线、问题排行和代表性原话同屏，而且每项分析都保留证据数量和回溯入口。 |

### 3.2 五项审美决策

| 项目 | 决策 | 为什么 |
|---|---|---|
| Typography | 阿里妈妈数黑体用于品牌名和标题，Noto Sans SC用于密集正文，JetBrains Mono用于数字。 | 延续现有字体角色，标题具辨识度，数字列更容易比较。 |
| Color & Theme | 炭黑占据绝大面积，风险红作为锐利强调，蓝青、绿色和黄色只承担明确语义。 | 贴近参考图，同时防止多色仪表盘分散注意力。 |
| Motion | 页面首次进入采用一次短促分层显现；筛选、行选中、抽屉和状态更新有明确过渡。 | 高密度工作界面需要反馈，不需要持续动画。 |
| Spatial Composition | 固定窄侧栏加顶部筛选区，概览采用8列趋势、4列热榜、4列证据的不对称网格。 | 参考图的紧凑结构适合大屏浏览，也让趋势、原因和证据形成连续阅读路径。 |
| Background Details | 图表区域使用低对比网格线，侧栏和内容区使用细微亮度差，风险选中行带半透明红色横带。 | 形成监测台氛围，但不让纹理影响中文阅读。 |

## 4. 全局应用壳

### 4.1 桌面结构

```text
┌──────────────┬──────────────────────────────────────────────────────┐
│ RedTrace     │ 时间范围  品牌范围                     数据日期/退出 │
│ 小红书舆情   ├──────────────────────────────────────────────────────┤
│              │ 页面标题、更新时间、采集健康状态                    │
│ ● 概览       ├──────────────────────────────────────────────────────┤
│ ○ 原因洞察   │                                                      │
│ ○ 内容库     │ 页面内容                                             │
│ ○ 品牌监控   │                                                      │
│ ○ 数据状态   │                                                      │
│              │                                                      │
│ 数据更新状态 │                                                      │
└──────────────┴──────────────────────────────────────────────────────┘
```

- 1440px及以上：侧栏宽188px，固定在左侧；主内容使用12列网格，最大宽度不强制压到窄版，左右各20px至24px。
- 1024px至1439px：侧栏缩为72px，仅显示品牌缩写和图标；导航文字通过可访问提示呈现。
- 768px至1023px：侧栏保持72px，概览从三列区域改为两列，证据区单独占一行。
- 767px以下：隐藏固定侧栏，使用五项底部导航；顶部筛选变为可打开的筛选抽屉。移动端不尝试复刻大屏密度。

### 4.2 侧栏

- 顶部品牌区显示红色`Red`与近白色`Trace`，下方为“小红书舆情监测系统”。
- 导航继续使用五项现有路由，名称不改：概览、原因洞察、内容库、品牌监控、数据状态。
- 导航图标采用统一16px至18px线性图标。当前项使用`--color-risk`背景或左侧实线，并同时提高文字字重，不能只靠颜色。
- 底部固定显示最后成功采集时间与采集健康状态。没有时间时写“尚无成功采集”，不显示“更新于--”。
- 数据模式不占据导航主区。模拟模式在侧栏底部与页面顶部同时提示，正式模式只在顶部元信息区显示一次。

### 4.3 顶栏

- 左侧放全局时间范围与品牌范围。第一阶段仍以现有`from`、`to`、`brandIds`参数为准。
- 品牌筛选应显示品牌名称，不继续要求非技术用户输入“品牌编号”；这需要前端复用品牌列表接口完成映射。
- 右侧显示当前数据截止时间、数据模式和安全退出。删除仅起装饰作用的日历按钮。
- 页面内的`PageHeader`压缩为一行或两行，不再占用大面积垂直空间。标题下只保留一句业务说明。

## 5. 信息层级

### 第一层级

- 负面内容数与负面占比。
- 最近时间范围内的负面趋势。
- 上升主题及其证据数量。
- 高风险原始内容。
- 采集是否正常、数据截至何时。

### 第二层级

- 帖子数与评论数。
- 品牌、品类和问题类型排行。
- 当前筛选范围。
- 进入内容库、原因洞察和数据状态的操作。

### 第三层级

- 发布时间、点赞数、分析来源、可信度、任务编号、版本号和采集时间。
- 模拟数据标识、请求编号和错误技术信息。

第一层级使用`--color-ink-primary`与有限的`--color-risk`；第二层级使用主文字和辅助文字；第三层级使用`--color-ink-tertiary`。不通过放大所有数字制造“重点”。

## 6. 概览页

### 6.1 数据边界

| 模块 | 现有数据来源 | 可以展示 | 暂不展示 |
|---|---|---|---|
| 核心统计 | `OverviewData.metrics` | 帖子数、评论数、负面数、负面占比 | 周同比、环比总量、日均负面量 |
| 趋势 | `sentimentTrend` | 每个时间桶的正向、中性、负向、未知数量 | 上周同期虚线，除非接口补充对比序列 |
| 热榜 | `risingTopics` | 主题名、变化比例、证据数 | 影响帖数、评论数，除非合同补充 |
| 代表证据 | `highRiskContents` | 原文摘要、类型、时间、点赞、风险、证据入口 | 未提供的评论数、品类名和品牌名 |
| 排行 | 品牌、品类、问题类型排行 | 合同中的名称和内容数；品牌另有负面数 | 参考图中的品类环比和主要问题TOP1组合 |
| 数据质量 | `collectionHealth`、`lastSuccessfulCollectionAt` | 健康状态与最后成功时间 | 覆盖率、重复率、延迟分钟、拦截数 |

可以从同一份`sentimentTrend`求和得到当前筛选范围的正向、中性、负向和未知总量，用于紧凑构成图，但必须与`metrics.negativeRatio`口径核对。若口径不一致，则不展示构成图。

### 6.2 1440px布局

```text
┌───────────────────────────────────────┬────────────────────┬────────────────────┐
│ 负面趋势，6列                         │ 上升主题，3列       │ 高风险证据，3列     │
│ 折线或阶梯线；下方帖子/评论/负面/占比 │ 主题、变化、证据数  │ 3至4条原文摘要      │
├───────────────────────────────────────┴────────────────────┴────────────────────┤
│ 品牌对比，4列             │ 品类排行，4列             │ 问题类型排行，4列      │
├─────────────────────────────────────────────────────────────────────────────────┤
│ 数据健康状态与最后成功时间；异常时提供“查看数据状态”                           │
└─────────────────────────────────────────────────────────────────────────────────┘
```

趋势区是视觉主角，占首行约一半宽度。上升主题和高风险证据同屏，形成“变化→原因→原文”的阅读顺序。趋势使用细网格、风险红主线，正向和中性通过蓝青实线、灰色虚线及图例符号区分。未知数据如果存在，进入表格，不强行加入主图。

### 6.3 概览组件

| 组件 | 类型 | 视觉与内容规格 | 状态 |
|---|---|---|---|
| `OverviewFilterBar` | 现有`FilterBar`的紧凑variant | 时间和品牌并排，标签始终可见；窄屏进入抽屉 | hover提升边界；active使用`--color-risk`细线；disabled降低文字和边界对比 |
| `TrendPanel` | 重做现有趋势面板 | 折线或阶梯线优先；下方四项统计使用同一连续区域，不拆成四张卡 | 加载时保留坐标和图例骨架；无数据时解释筛选范围 |
| `RisingTopicTable` | 重做`topic-spine` | 每行显示序号、主题名、变化比例、证据数和进入洞察箭头 | 变化未知时写“暂无对比”，不显示0% |
| `EvidenceQueue` | 复用`EvidenceItem`的紧凑variant | 每条最多三行原文；风险、内容类型、发布时间在顶行；底部显示点赞和证据入口 | 无内容时写“当前范围没有高风险证据”，不等同采集失败 |
| `CompactRanking` | 现有排行variant | 品牌、品类、问题类型各自独立，不合并字段；数值右对齐 | 整行可点击并把筛选写入URL |
| `HealthFooter` | 重做`DataHealth` | 正常状态保持低调；延迟、部分成功和失败才增强视觉 | 图标、文字和颜色共同表达，不使用单独彩色圆点 |

## 7. 状态、错误与空数据

### 7.1 错误分类

| 场景 | 标题 | 说明与操作 | 页面其余内容 |
|---|---|---|---|
| `DATA_NOT_READY` | 统计分析正在准备 | 说明原始采集数据仍保留；提供“查看内容库”“查看数据状态”“重新加载” | 没有可用概览数据时显示说明面板，不渲染假图表 |
| `DEPENDENCY_UNAVAILABLE` | 数据服务暂时不可用 | 显示上次成功时间；提供重试和数据状态入口 | 如果前端仍有上次成功响应，则保留旧数据并加“数据截至”标识 |
| 网络错误 | 无法连接数据服务 | 提醒检查网络或稍后重试，保留请求编号 | 初次加载失败时显示紧凑故障面板，不留下大面积无说明空白 |
| `AUTH_REQUIRED` | 登录状态已失效 | 提示重新登录 | 跳转登录页并保留原目标路由 |
| 合同解析错误 | 数据格式异常 | 显示请求编号并建议联系维护人员 | 禁止猜测字段或局部渲染错误数据 |

错误使用左侧风险线、警示图标、标题、可读说明和操作按钮。错误横幅不能占满整个可视区，也不能只用一大片浅红色背景。详细请求编号放在可展开的“技术信息”中，默认不抢占业务信息。

### 7.2 空数据与加载

- 尚未采集：显示品牌启用状态、首次采集说明和“前往品牌监控”。不显示0条舆情。
- 筛选无结果：保留当前筛选条件，提供清除筛选。不要跳到品牌监控。
- 暂无分析：允许继续进入原始内容库，说明DeepSeek分析尚未完成或没有有效证据。
- 高风险为空：说明当前筛选范围没有高风险证据，这是正常业务结果。
- 加载中：按最终网格显示静态骨架；禁止整页旋转图标；超过400ms再显示骨架，避免快速请求闪烁。
- 刷新中：保留旧数据，顶部显示细进度条或面板标题中的加载标记；不要把整页透明度降到难以阅读。

### 7.3 模拟模式

- 顶部出现不可关闭的提醒条，文字为“当前为模拟模式，页面数据仅用于界面验收，不代表真实舆情”。
- 每个数据面板保留“模拟数据”标识，但改为水平小标签，不再旋转成印章。
- 模拟证据不显示可打开的原帖链接；按钮保留禁用说明。
- 正式模式不显示模拟相关占位和文案。

## 8. 其余页面如何继承

### 8.1 原因洞察

- 继承暗色侧栏、紧凑页头、全局筛选和面板样式。
- 保持负面原因与正向卖点分段切换，不把情感与问题类型合并。
- 桌面端采用“主题排行4列＋关键词4列＋证据4列”。选中主题使用风险色左线和深红底；证据侧栏保持粘性。
- 主题只展示合同已有的内容数、帖子数、评论数、用户数、点赞数、变化比例和证据数。
- 没有证据的主题不得进入正式排行；低可信度必须同时显示文字和图标。

### 8.2 内容库

- 桌面端采用“内容列表8列＋证据预览4列”，筛选条默认横向紧凑排列；高级筛选放入可展开区域。
- 帖子和评论分段控件放在列表标题旁，内容总数与分页在同一水平线上。
- 每行显示原文摘要、内容类型、风险、情感、发布时间、点赞、分析来源和可信度。现有合同没有的品牌名、品类名不得凭ID猜测。
- 原文摘要保持较高行高，避免暗色高密度界面变成终端日志。
- 内容详情延续三栏结构：原文、上下文、人工修正。移动端按此顺序纵向排列。

### 8.3 品牌监控

- 继续使用“监控品牌”和“分类词表”二级标签。
- 台账采用暗色数据表，品牌名称固定在首列；状态、相关词数量、最后采集、最近任务和操作对应现有合同。
- “立即更新”是行内主操作；编辑、启停使用次级操作。运行中必须禁用更新并写明原因。
- 编辑抽屉使用`--color-surface-raised`，宽度保持560px；表单label、帮助文本、错误提示完整保留。

### 8.4 数据状态

- 顶部先显示采集结论：正常、部分成功、连续失败、数据量异常或汇总不可用。
- 24小时心跳改为细条时间轴，状态同时使用图标和文字；任务台账继续承载完整信息。
- 只展示合同已有的最后成功时间、连续失败次数、数据量异常标记及任务成功/失败帖子数。
- 不引入参考图中的覆盖率、延迟分钟、重复率和风险拦截数，除非后端增加真实统计。

### 8.5 登录页

- 使用双栏暗色布局。左侧保留“发现负面变化，回看原始证据”的产品主张，并用一条风险红轨迹线表现追溯；右侧放宽度不超过432px的登录表单。
- 输入框、显示密码、提交中、错误和禁用状态沿用全局控件规范。
- 移动端隐藏纯装饰轨迹，只保留品牌、主张和表单；登录错误不回显服务端内部信息。

| 组件 | 复用关系 | 规格与约束 |
|---|---|---|
| `AppShell` | 重做现有 | 侧栏、顶栏、模拟模式条和主内容区统一；保留未保存修正的离开确认 |

## 10. 交互与动效

- 页面进入：主要区域按阅读顺序以`--motion-enter`淡入并上移4px，仅执行一次。动机是建立趋势、原因、证据的阅读顺序。
- 导航与行选中：使用`--motion-fast`改变背景、边界和文字；不缩放卡片。
- 筛选刷新：旧数据保留，顶部进度线使用`--motion-base`；完成后只更新数值，不整页闪烁。
- 抽屉：遮罩淡入，抽屉从右侧进入，时长使用`--motion-enter`。
- 保存修正：按钮进入提交状态，成功后在原位显示状态反馈并更新人工修正标识。
- 图表点选：键盘和鼠标均可进入对应内容列表；tooltip不作为唯一信息来源，下方保留可访问表格。
- `prefers-reduced-motion: reduce`下关闭位移、循环动画和顺滑滚动，只保留即时状态切换。

## 11. 工程正确性底线

- 所有图标按钮都有可访问名称，触控区域不小于44px。
- 导航、分段控件、列表选择和图表数据点可使用键盘操作，并有清晰焦点环。
- 风险、成功、提醒和禁用状态同时依赖图标、文字或线型，不单独依赖颜色。
- 外链继续使用新标签页与`noopener noreferrer`。
- 表单label保持可见，placeholder不替代label；提交错误与对应字段关联。
- 中文标题正常字距，正文允许合理换行；英文ID和长URL必须可断行或省略。
- 固定侧栏、粘性证据栏和抽屉不能遮挡页面焦点；移动端底部导航需要为页面预留安全区域。
- 面板和文字组合需要通过WCAG AA对比度检查；正文至少4.5:1，大字至少3:1。
- 不把`DATA_NOT_READY`改写成“数据库连接失败”，错误标题必须忠实反映服务端错误码。

## 12. 给code-writer的交付说明

1. 先改`styles.css`中的现有token值和应用壳样式，再处理公共组件variant，最后调整各页面布局。不要同时引入新的CSS框架。
2. 保留现有路由、API客户端、URL筛选、会话保护、模拟模式、原始链接安全属性和未保存修正确认。
3. 优先复用`Panel`、`StatusBadge`、`ErrorNotice`、`EmptyState`、`FilterBar`、`EvidenceItem`、`DataHealth`，通过variant扩展，不复制同功能组件。
4. 第一批实施范围建议为`app-shell.tsx`、公共组件、`overview.tsx`和`styles.css`。其余页面先继承新token与壳层，再逐页精修。
5. 概览只消费`OverviewData`现有字段。任何新增指标必须先修改合同、MySQL查询和测试，再进入界面。
6. 图标使用统一的内联SVG组件或轻量图标依赖，不使用emoji、字体图标和不可访问的CSS字符。

反AI套路自检：配色没有紫色渐变，布局没有四张等宽大数字卡，面板没有玻璃拟态和大圆角，视觉特征来自“趋势、原因、证据同屏”的业务结构。字体、颜色、动效、空间和背景均有明确用途。
