# 项目错误记录

## 2026-08-06：Workbench 多行粘贴预览暴露数据库凭据

- 严重程度：严重。
- 现象：通过 Workbench 终端关闭回显后粘贴 `.env.local` 时，Workbench 在终端之外弹出多行粘贴预览框；随后读取页面状态时，一部分数据库凭据进入了受控操作回显。
- 影响：远端配置文件未写入，文件保持为空；已取消预览并清空浏览器剪贴板。已经暴露的数据库应用账号密码必须轮换后才能继续部署。
- 根本原因：只考虑了终端回显和 Shell 历史，没有把 Workbench 自带的多行粘贴确认界面纳入数据暴露边界。
- 强制规则：禁止通过终端多行粘贴、命令行参数、Shell 历史、页面预览或聊天内容传输密钥、密码、Cookie、Token 和完整环境文件。
- 后续做法：秘密配置只能通过不会显示文件正文的文件上传、受控秘密管理服务或用户在服务器端的隐藏输入流程传递。任何上传控件失效时必须停止并请求用户恢复安全传输通道，不能改用多行粘贴绕过。

## 2026-08-07：未验证本地登录链路却宣称线上接口可用

- 严重程度：严重。
- 现象：向用户交付本地前端地址时，宣称本地前端继续使用线上接口且验证已经通过；用户实际登录后只看到“账号或密码不正确，或当前账号暂时无法登录”。随后只读诊断发现，本地前端的会话接口返回纯文本500，并未返回线上API约定的结构化认证响应。
- 影响：用户被错误引导去怀疑没有修改过的账号密码；本地预览无法进入受保护页面，先前关于“使用线上接口”的交付结论不成立。
- 根本原因：第一层是本地Vite代理目标没有实际生效，代理回退到没有服务监听的本机API端口；第二层是交付前只验证了页面、构建和测试，没有执行“提交登录—接收Cookie—再次读取会话”的端到端验证。同时，登录页把代理、网络和认证等不同异常统一显示为账号或密码错误，掩盖了真实故障。
- 强制规则：凡是宣称本地前端已经接入线上接口，交付前必须实际验证至少一个无需秘密的线上API响应，并完成一次由用户输入凭据的登录与会话保持验证；不得用构建通过、页面可打开或接口配置存在替代运行时验证。
- 后续做法：登录错误必须区分凭据错误、服务连接失败和响应格式错误；本地代理配置完成后先验证会话接口返回结构化响应，再由用户在浏览器中输入凭据，并验证登录后的会话读取。没有完成这些检查时，只能说明服务已经启动，不能宣称登录链路或线上接口已经可用。

## 2026-08-07：PowerShell拼接远端awk命令导致数据库旧密码回显

- 严重程度：严重。
- 现象：通过PowerShell拼接SSH远端诊断命令时，在双引号字符串中嵌入了awk的`$1`。PowerShell先对变量进行了解析，导致远端命令没有按照预期只输出配置键名，数据库旧密码值意外进入内部工具输出。
- 影响：旧数据库密码已经发生意外回显，不能再被视为安全凭据，也不得恢复使用。错误输出和后续文档均不得记录该值本身。
- 根本原因：把本地PowerShell、SSH和远端awk三层解析混在一条命令中，没有先建立只允许返回键名和布尔状态的输出边界，也没有验证`$n`在本地Shell中的转义结果。
- 强制规则：涉及远端环境文件时，只允许使用键名白名单以及经过审查的安全脚本或标准输入传递；禁止在PowerShell双引号字符串中嵌入awk的`$n`字段引用。任何凭据意外回显后都必须立即轮换，且禁止恢复旧值。
- 后续做法：远端配置诊断只能输出“键是否存在、长度是否合规、服务是否运行”等非秘密状态。需要awk等远端脚本时，使用不会经过PowerShell变量插值的安全脚本或标准输入，并在执行前用无秘密样例验证实际传递内容。
